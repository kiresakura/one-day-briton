# 湊人數機器人

測試多人連線版（`play/`）時人不夠，可以放幾個「機器人玩家」坐進主持端開好的房間。機器人用跟手機玩家一樣的流程加入，之後自己出牌、響應、投票、選黑夜、挑棄牌；**開局、按「下一階段」、算分、開第 2 場照常由主持端做**。一個人就能在主持端畫面上看完整場流程，也可以再用手機坐一個位子一起玩。

機器人只當玩家，不當主持人；只碰你給的那個房號，不改規則，不刪別人的資料或遊戲資料。它只刪自己的兩樣東西：離線時拿掉自己的在線標記；開局前結束時，像手機按「離開」一樣把自己從玩家名單上拿掉（見下面的「結束」）。

## 第一次用之前

在專案資料夾（有 `package.json` 的那一層）開終端機，跑一次：

```sh
npm install
```

需要 Node.js 22 以上。連本機模擬器的話另外要 Java 21 以上（見 [`play/README.md`](../play/README.md) 的「需要什麼」）；只連正式站不需要 Java。

## 用法（五步）

1. **開房**：在主持端畫面按「開房」，記下畫面上的 6 碼房號（例如 `K7MXQ2`）。
2. **（可選）自己坐一個位子**：用手機照平常的方式加入，選你要坐的那一桌。
3. **放機器人**：在專案資料夾的終端機跑

   ```sh
   npm run bots -- --room K7MXQ2
   ```

   沒指定桌號時選還沒開局、人最少的一桌，補到 3 人（建議的開局人數）。連正式站時會先倒數 5 秒才開始寫入（見下一節）。看到「都入座了，等主持端開局」就可以了。
4. **看流程**：主持端照常按「開始」、「下一階段」。終端機每一行是一個機器人的一個動作；主持端與手機畫面上看得到同樣的變化。
5. **結束**：兩場都結束後，終端機印出每一場的結算與兩場合計，機器人自己離線、指令結束。中途要停就在終端機按 `Ctrl-C`：機器人先收好再結束（卡住的話隔一秒以上再按一次 `Ctrl-C`，就不等、直接結束；一秒內連按算同一次）。**請用 `Ctrl-C`，不要直接關掉終端機視窗**：關視窗時機器人也會盡量收好，但你看不到收好了沒有。
   - **還沒開局**時停掉（或機器人等太久自己走）：機器人會離開玩家名單，跟手機按「離開」一樣。之後主持端開局，不會把它排進座位。
   - **開局之後**才停掉：機器人留在玩家名單上（成績表要用它的名字），只是離線。它的座位之後沒人動：白晝輪到它時要主持端按「下一階段」，黃昏、黑夜也湊不到「全員送出」，要主持端手動揭曉。所以開局之後請讓機器人打完；不玩了就重開一間房。
   - **第 1 場結束後、第 2 場開局前**停掉：機器人一樣留在名單上（第 1 場有成績），主持端開第 2 場時預設會把它排進座位。指令結束時會提醒「開第 2 場時請在「勾選參加」把離線的機器人取消」：開第 2 場時打開「勾選參加」，把這些機器人改成「不參加」再按開始。

**一定要在主持端按「開始」之前放機器人**：開局之後才進來的人沒有座位，機器人會說明原因、離開玩家名單後自己結束。

**一個房間一次只跑一個指令**：兩個終端機同時對同一個房間放機器人，兩邊會照同一份舊資料排座位，可能撞名、或讓一桌超過 6 人。指令在都入座之後會再看一次房間，多出來的（較晚加入的）機器人會說明原因後離開；不過主持端已經按了「開始」的話，就不請機器人離開（離開了座位就沒人動），只印一行提醒。要多放幾個，等前一個指令印出「都入座了」再跑下一個，或直接用 `--count`。

### 連正式站，還是本機模擬器

| 你在哪裡開房 | 指令 |
|---|---|
| 正式網站（<https://kiresakura.github.io/one-day-briton/play/>） | `npm run bots -- --room K7MXQ2` |
| 本機模擬器（先在另一個終端機跑 `npm run dev`，開 <http://127.0.0.1:5050/>） | `npm run bots -- --room K7MXQ2 --emulator` |

不加 `--emulator` 就是連**正式站**：機器人是寫進正式資料庫的真玩家（各自一個匿名身分），房間結束後也不會自動刪除，跟手機玩家一樣。指令一開始會先印連到哪裡，接著倒數：

```text
連線：正式站（專案 one-day-briton）
5 秒後開始寫入正式站（專案 one-day-briton），按 Ctrl-C 取消
```

連錯了就在這 5 秒內按 `Ctrl-C`，會印出「收到 Ctrl-C：還沒有入座，資料庫沒有寫入任何東西，結束」。連本機模擬器不倒數。

**正式站的匿名帳號有上限**：每跑一次，每個機器人都會在正式站新開一個匿名帳號。Firebase 規定同一個網路（同一個對外 IP）每小時最多新開 100 個匿名帳號，超過之後一段時間內都登入不了。所以：

- 反覆測試請用本機模擬器（`--emulator`），模擬器沒有這個限制。
- 活動現場不要在玩家手機用的同一個網路（例如教室 Wi-Fi）上一直放機器人：機器人用掉的是同一份額度，玩家的新手機會進不了房。

### 選項

| 選項 | 意思 | 不給的話 |
|---|---|---|
| `--room <房號>` | 要加入的房間（必填；大小寫、空白都可以） | — |
| `--count <人數>` | 放幾個機器人 | 補到這一桌 3 人；已經 3 人以上就不放 |
| `--table <桌號>` | 坐第幾桌 | 還沒開局、人最少的一桌（同樣多選號碼小的） |
| `--delay <最少-最多>` | 每個動作前隨機等多久（毫秒），讓旁觀的人看得到 | `1500-4000` |
| `--fast` | 動作前只等 50–150 毫秒（測試用，會蓋過 `--delay`） | — |
| `--emulator` | 連本機模擬器 | 連正式站 |
| `--name-prefix <前綴>` | 名字的前綴 | `機器人`（機器人1、機器人2…） |
| `--wait <分鐘>` | 還沒開局時，這麼久主持端都沒有動作就自己離開 | `20` |
| `--help` | 顯示說明 | — |

一桌最多 6 人。要放的比空位多時，只放得下的那幾個，並印出原因。名字已經有人用（例如同一個房間先前放過機器人）就跳過那個號碼。

名單上的人不論在不在線都算已經入座（手機可能只是暫時離線，開局時一樣會排進座位）；有人離線時會印出名字提醒，例如「第 1 桌名單上有 1 人離線：小明（開局時一樣會排進座位）」。真的不會回來的人，請他在手機上按「離開」，不然開局後他的座位沒人動。

`--wait` 只管還沒開局這一段。**坐在一局還沒結束的遊戲裡時，機器人不會因為等太久離開**（離開了座位就沒人動，也回不來）；主持端中場休息、講解很久時，它每隔幾分鐘（最多 5 分鐘、`--wait` 比較短就照 `--wait`）印一行「還在等主持端或其他玩家…」，主持端繼續之後照常玩。

**坐過第 1 場、等第 2 場時也不會因為等太久離開**：第 1 場有成績，它離不開名單，主持端開第 2 場時預設還是會把它排進座位，走了就是不會動的座位。它同樣每隔幾分鐘印一行「還在等主持端開第 2 場（不想讓機器人參加第 2 場，開第 2 場時在「勾選參加」把它取消）；要結束請按 Ctrl-C」。不玩第 2 場就按 `Ctrl-C` 結束，再照上面「結束」說的在「勾選參加」把它們取消。

例子：

```sh
npm run bots -- --room K7MXQ2 --table 2 --count 4      # 第 2 桌放 4 個
npm run bots -- --room K7MXQ2 --fast --emulator        # 本機測試，動作快
npm run bots -- --room K7MXQ2 --delay 3000-6000        # 動作慢一點，方便講解
```

## 終端機每一行怎麼讀

```text
00:44:11 機器人1｜第 1 桌第 1 場｜第 1 回合・白晝｜出牌 線民情報（付 1 英鎊）
```

依序是：時間、哪一個機器人、第幾桌第幾場、第幾回合與階段、做了什麼。常見的動作：

- 白晝：`出牌 …（付 …）`、`出牌 …，指定 機器人2`、`結束這一輪`、`響應 …（回應 … 的 …）`、`響應成功：…`
- 黃昏：`表決 贊成・出價 2 影響力`、`表決 棄權`
- 黑夜：手牌超過上限時先 `手牌超過上限 7 張，挑這幾張在天亮時棄掉：…`，再 `黑夜 豪賭（賭到第 2 層）`、`黑夜 分贓` 或 `黑夜 睡覺`
- 第 2 場：`入座：座位 2・…（第 2 場的新階層，由座位 1 的 機器人3 交過來）`

每一場結束會印一段「第 1 桌第 1 場結算」，第 2 場結束再印「第 1 桌兩場合計」；有天命還要主持人判定時，標題後面會加「（天命待判定，總分未定）」，總分以主持端判定後的畫面為準。最後每個機器人一行總結，例如：

```text
機器人1 結束：收到停止（Ctrl-C），已離開玩家名單｜出牌 0、結束這一輪 0、響應 0、表決 0、黑夜 0、挑棄牌 0、被退回 0、送不出去 0
```

「已離開玩家名單」表示它在開局前結束、已經從名單上拿掉；沒有這幾個字就是留在名單上（開了局的）。

## 機器人怎麼決定

- 白晝輪到它：從出得了的牌裡隨機挑一張（付得起、不是響應卡；要指定對象的隨機挑同桌一人），偶爾直接結束這一輪；同一輪出越多張，越可能停手。
- 別人出牌、自己手上有能響應的牌：大約四次裡響應一次。
- 黃昏：大約五次裡棄權一次，其餘隨機選贊成或反對，出價 0 到自己目前的影響力。
- 黑夜：手牌超過上限就先隨機挑多出來的張數棄掉（這一回合結束就算分時不用棄），再從豪賭（隨機賭到第 1–3 層）、分贓、睡覺三選一。

能不能出、能不能響應、票與選擇合不合法，用的是跟手機畫面同一套規則判斷；主持端結算時照樣會再查一次。

## 常見的訊息

| 訊息 | 意思與處理 |
|---|---|
| `5 秒後開始寫入正式站（專案 one-day-briton），按 Ctrl-C 取消` | 正式站模式的倒數。連錯了就在這時按 `Ctrl-C`。 |
| `收到 Ctrl-C：還沒有入座，資料庫沒有寫入任何東西，結束` | 在入座前按了 `Ctrl-C`（例如倒數時），什麼都沒寫。 |
| `收到 Ctrl-C：機器人斷線中…（卡住的話再按一次 Ctrl-C）` | 機器人正在收好：開局前的離開玩家名單，再離線。 |
| `又收到一次停止：不等機器人收好，直接結束` | 第二次按 `Ctrl-C`。開局前的機器人可能還留在名單上，請在主持端畫面確認。 |
| `找不到這個房間：房號打錯了，或房間已經不在了。資料庫沒有寫入任何東西。` | 房號打錯，或連錯地方（正式站開的房要用不加 `--emulator` 的指令，反之亦然）。 |
| `第 1 桌已經開局，開局後不收新玩家` | 主持端已經按了開始。換一桌（`--table`），或重開一間房、先放機器人再開始。 |
| `第 1 桌已經開了第 2 場，第 2 場不收新玩家` | 第 2 場只給第 1 場同桌的人。 |
| `第 1 桌已經坐滿 6 人` | 換一桌。 |
| `這個房間沒有可以加入的桌：每一桌都已經開局或坐滿了` | 同上，或重開一間房。 |
| `第 1 桌已經有 3 人，到了建議的開局人數（3 人），不用補；要多放請加 --count` | 不用補人；真的要多放就加 `--count 2` 之類。 |
| `… 只放得下 2 個（要放 4 個）` | 空位不夠，只放了放得下的。 |
| `第 1 桌名單上有 2 人離線：機器人1、機器人2（開局時一樣會排進座位）` | 名單上有人不在線。不會回來的請他按「離開」；要是先前的指令被強制結束、留下了機器人，重開一間房最省事。 |
| `注意：機器人1 跟較早加入的人同名，離開（同一個房間請一次只跑一個指令）` | 另一個指令同時在放機器人，撞名的較晚那個離開。 |
| `注意：機器人7 讓第 1 桌超過一桌 6 人，離開（同一個房間請一次只跑一個指令）` | 同上，超過一桌人數上限的較晚那個離開。 |
| `注意：第 1 桌已經開局，機器人1、機器人2 不離開，有座位的照常玩（同一個房間請一次只跑一個指令）` | 同上，但主持端已經按了「開始」：名字重複也照常玩（沒有座位的會自己結束）。下次一個房間只跑一個指令。 |
| `注意：第 1 桌名單上有 7 人，超過一桌 6 人，主持端開不了局；請有人換桌或按「離開」` | 多出來的機器人離開之後隔一下再數一次，還超過才印：多出來的是真人，請有人換桌或離開，或按 `Ctrl-C` 讓機器人離開。 |
| `機器人3 沒有入座：…` 接著 `中止：已經入座的機器人離開中…` | 入座途中出錯：已經入座的機器人離開名單後結束（以 1 結束）。 |
| `被退回（出牌 …）：英鎊或影響力不夠付這張牌的成本，改做別的` | 主持端判定這一步不行。偶爾發生沒關係，機器人會改出別張或結束這一輪。 |
| `送不出去：這張票沒有送出（可能已經截止…）` | 剛好截止之類，隔一下再試，最多 3 次。 |
| `主持端 20 秒都沒處理，再送一次（…）` | 主持端畫面可能關掉或斷線了：打開主持端畫面，結算會接著做。 |
| `這一輪送不出去，請主持端按下一階段（30 秒後再送一次結束這一輪）` | 這一輪機器人怎麼送都不成：請主持端按「下一階段」。機器人隔 30 秒會再送一次「結束這一輪」，最多 2 次。 |
| `還在等主持端或其他玩家（房間 5 分鐘沒有變動）；這一局還沒結束，機器人不會自己離開` | 主持端或某位玩家很久沒動作。機器人照樣等；主持端繼續就好。 |
| `這一桌開局時沒有我的座位（開局之後才進來）` | 機器人在按「開始」之後才加入，沒有座位，離開名單後自己結束。 |
| `第 2 場沒有我的座位（主持端設為不參加）` | 主持端開第 2 場時沒讓它參加，自己結束（第 1 場的成績還在，留在名單上）。 |
| `這一場結束了。主持端開第 2 場的話會跟著玩；不開的話按 Ctrl-C 結束` | 第 1 場結束；不玩第 2 場就按 `Ctrl-C`。 |
| `還在等主持端開第 2 場（不想讓機器人參加第 2 場，開第 2 場時在「勾選參加」把它取消）；要結束請按 Ctrl-C` | 第 1 場結束後很久沒開第 2 場。機器人照樣等，不會自己離開；主持端開第 2 場就好。 |
| `開第 2 場時請在「勾選參加」把離線的機器人取消（機器人1、機器人2）` | 在第 1 場結束後、第 2 場開局前停掉了機器人：它們留在名單上，開第 2 場時在「勾選參加」改成「不參加」，不然它們的座位沒人動。 |
| `房間 20 分鐘都沒有變動` | 還沒開局時太久沒動靜，機器人自己結束（時間可用 `--wait` 改；數字照你給的印）。 |
| `連不上本機模擬器（…）；模擬器要先在另一個終端機跑 npm run dev。資料庫沒有寫入任何東西。` | 用了 `--emulator` 但模擬器沒開。 |
| `連不上正式站（…）；請確認網路。資料庫沒有寫入任何東西。` | 網路有問題。 |
| `登入被 Firebase 暫時擋下：同一個網路一小時內新開的匿名帳號太多（每個 IP 每小時最多 100 個）。…` | 見上面「正式站的匿名帳號有上限」。隔一段時間再試，反覆測試改用 `--emulator`。 |
| `npm error Missing script: "bots"` | 不在專案資料夾，或程式碼太舊：先到專案資料夾、更新到最新版。 |

拒絕的訊息後面都會接「資料庫沒有寫入任何東西」：這時還沒有寫進資料庫。不過連正式站時，登入那一步已經用掉了匿名帳號的額度（見上面）。

機器人的牌名與規則數字讀的是你電腦上的 `play/data/`。網站上的卡牌資料比你的新時，偶爾會有動作被主持端退回，不影響進行；更新到最新版即可。
