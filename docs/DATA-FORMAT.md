# 卡牌資料格式（給填資料的人）

遊戲用到的卡牌與數值放在 `play/data/` 的七個資料檔（教學提示可以沒有）。資料在試算表裡填，一列一張；匯出成 CSV 後，一個指令就轉成資料檔，同時自動檢查填錯的地方。

樣板在 [`docs/data-templates/`](data-templates/)，每種資料一個 CSV，裡面的範例列可以照著改。

## 怎麼填、怎麼交

1. **開樣板。** Google 試算表：開一份新的試算表，「檔案 → 匯入 → 上傳」選一個樣板，匯入位置選「插入新工作表」；七個樣板各匯入一次，工作表名稱照樣板檔名或改成中文（見「檔名」）。Excel：直接打開樣板 CSV，另存成 .xlsx 再填。
2. **照下面各節填。** 第一列的欄名不要改；欄的順序可以換；可以自己加欄（例如寫給自己看的說明），匯入時會略過並提醒。範例列刪掉或直接改成正式資料都可以。
3. **匯出 CSV，一種資料一個檔。**
   - Google 試算表：切到那個工作表，「檔案 → 下載 → 逗號分隔值（.csv）」。下載的檔名是「試算表名稱 - 工作表名稱.csv」，不用改。
   - Excel：「另存新檔」，格式選「CSV UTF-8（逗號分隔）」。不要選沒有 UTF-8 字樣的「CSV（逗號分隔）」，中文會變亂碼。
   - Numbers：「檔案 → 輸出至 → CSV」，文字編碼選 Unicode（UTF-8）。
4. **交給工程。** CSV 放進同一個資料夾（只改了幾種就只放那幾種），工程在專案根目錄執行：

   ```sh
   npm run data:import -- <放 CSV 的資料夾>
   ```

   轉好的資料檔寫到 `play/data/`，接著自動檢查。只想檢查現有的資料檔時用 `npm run data:check`；`npm test` 也會跑同一個檢查。
5. **看結果。** 有「錯誤」就照訊息改試算表、重新匯出再匯入；只有「警告」可以先不管（例如效果還沒換算）。

試算表是正本。資料檔可以手改（改完跑 `npm run data:check`），但下次匯入會整個蓋掉。

## 檔名

匯入時依檔名判斷是哪一種資料，大小寫不拘；認不出的檔會列出「略過」，不會匯入。

| 資料 | 樣板 | 也認得的工作表名稱 | 轉成 |
|---|---|---|---|
| 設定 | `settings.csv` | 設定 | `play/data/settings.json` |
| 階層 | `roles.csv` | 階層 | `play/data/roles.json` |
| 行動牌 | `actions.csv` | 行動牌 | `play/data/actions.json` |
| 法案 | `bills.csv` | 法案 | `play/data/bills.json` |
| 事件 | `events.csv` | 事件 | `play/data/events.json` |
| 隱藏天命 | `destinies.csv` | 隱藏天命 | `play/data/destinies.json` |
| 教學提示 | `tutorial.csv` | 教學提示 | `play/data/tutorial.json` |

例如 `events.csv`、`事件.csv`、`卡表 - 事件.csv` 都會當成事件。

## 共通規則

- **一列一張**（設定是一列一項）。整列空白的會略過。
- **編號**：每張表自己編，同一張表內不可重複；只能用英文字母、數字、`-`、`_`，最多 32 個字。建議字母開頭加流水號，例如階層 `r1`–`r6`、行動牌 `a01`、法案 `b01`、事件 `e01`、天命 `d01`。純數字或 `1e5` 這種在試算表裡可能被改成別的數字，不要用。
- **數字欄**：填整數，全形數字也可以。看不懂的（例如「兩」）匯入時原樣保留，檢查時會報錯。
- **文字欄**：可以在儲存格內換行；前後的空白會去掉。
- **空白**：各節表格的「空白時」寫著空白代表什麼；寫「必填」的不可空白。
- 「備註」欄與自己加的欄都不會匯入。

## 效果的寫法

行動牌的「效果」、法案的「通過時效果」「不通過時效果」、事件的「效果」都用同一種寫法：一個效果是「項目」，後面可以接「@對象」。

| 項目 | 意思 | 例子 |
|---|---|---|
| `英鎊+數字`、`英鎊-數字` | 拿或付英鎊 | `英鎊+5`、`英鎊-3` |
| `影響力+數字`、`影響力-數字` | 拿或付影響力 | `影響力+2` |
| `迷霧+數字`、`迷霧-數字` | 迷霧值增減；迷霧是全桌一個值，**不寫對象** | `迷霧+3`、`迷霧-5` |
| `抽牌數字` | 抽牌，也可以寫 `抽2張` | `抽牌2` |
| `棄牌數字` | 棄牌，也可以寫 `棄1張` | `棄牌1` |
| `抵銷` | 被回應的那張牌效果不發生；不寫數量、不寫對象。**只能用在響應卡** | `抵銷`、`抵銷；英鎊+2@自己` |
| `偷英鎊數字`、`偷影響力數字` | 從對象那裡拿走英鎊或影響力：對方實際少多少，自己就拿多少（對方不夠就只拿到對方有的）。**只能用在行動牌**，對象只能是 `@指定`（一般牌）或 `@出牌者`（響應卡） | `偷英鎊3@指定`、`偷影響力2@出牌者` |

| 對象 | 意思 |
|---|---|
| `@自己` | 出這張牌的人；響應卡是打出響應卡的人 |
| `@全體` | 該桌所有人（包括自己） |
| `@其他人` | 該桌除了自己以外的人 |
| `@指定` | 指定的一個人 |
| `@階層編號` | 該階層的玩家，例如 `@r2`；編號要是階層表裡有的。行動牌、法案、事件都能用 |
| `@出牌者` | 被回應的那張牌是誰出的。**只能用在響應卡** |

- 英鎊、影響力、迷霧一定要寫 `+` 或 `-`；數量是整數，不可以是 0。抽牌、棄牌至少 1 張。
- 偷的數量是 1 以上的整數，不寫 `+`、`-`；一定要寫對象：一般牌只能寫 `@指定`、響應卡只能寫 `@出牌者`（沒寫對象會當成 `@自己`，檢查時報錯）。寫在法案或事件、用別的對象、數量不是 1 以上的整數都會報錯。
- 沒寫對象時：行動牌當作 `@自己`，法案與事件當作 `@全體`。
- 法案與事件沒有「出牌的人」，對象只能用 `@全體`、`@指定` 或 `@階層編號`。
- `抵銷` 和 `@出牌者` 只能用在響應卡，寫在一般牌、法案、事件會報錯。`抵銷` 後面接 `@對象` 看不懂，會標成 todo。
- `@階層編號` 的編號寫錯（階層表沒有）會報錯；那個階層這一桌沒人坐時，效果打不到人。
- 一格裡有好幾個效果時用分號隔開（`；` 或 `;`），逗號、頓號、換行也可以。空白、全形字都沒關係。
- 效果欄可以空白，代表沒有效果；檢查時會提醒一聲，故意的就不用管。

例子：

| 寫法 | 轉成資料檔裡的 |
|---|---|
| 行動牌 `英鎊+5@自己；迷霧+3` | `[{ "op": "pounds", "target": "self", "amount": 5 }, { "op": "fog", "amount": 3 }]` |
| 行動牌 `影響力-1@其他人；抽牌1` | `[{ "op": "influence", "target": "others", "amount": -1 }, { "op": "draw", "target": "self", "amount": 1 }]` |
| 事件 `英鎊-2；棄牌1@指定` | `[{ "op": "pounds", "target": "all", "amount": -2 }, { "op": "discard", "target": "chosen", "amount": 1 }]` |
| 法案 `英鎊-4@r2；影響力+2@r3` | `[{ "op": "pounds", "target": "role", "role": "r2", "amount": -4 }, { "op": "influence", "target": "role", "role": "r3", "amount": 2 }]` |
| 響應卡 `抵銷；英鎊-2@出牌者` | `[{ "op": "cancel" }, { "op": "pounds", "target": "originalPlayer", "amount": -2 }]` |
| 一般牌 `偷英鎊3@指定` | `[{ "op": "steal", "resource": "pounds", "target": "chosen", "amount": 3 }]` |
| 響應卡 `偷影響力2@出牌者` | `[{ "op": "steal", "resource": "influence", "target": "originalPlayer", "amount": 2 }]` |

**寫不成這種格式的效果**（例如「偷看一張手牌」「休戰一回合」）照常寫進效果欄。只要一格裡有看不懂的片段，匯入時那一格整格先不結算：效果留空，原文留在資料檔的 `todoText`，整筆標成 `todo`。這只算警告、不算錯誤，匯入時會列出是哪幾個字看不懂；之後再決定這些效果怎麼做。

## 設定（settings.csv）

三欄：「項目」「值」「說明」（說明不會匯入）。項目名稱照樣板寫，一列一項、順序不拘。下面的值是暫定值：響應等待秒數是工程先放的，日出一般事件張數是企劃 10/15 回「照建議」的，黑夜的七項（黑夜揭曉倒數秒數到分贓罪孽）是企劃 10/15 第 8 題雛形的數值，終局與計分的五項（回合上限到罪孽扣分換算）是企劃 10/15 第 9、11 題的數值（計分值 10/15 定案，回合上限是程式的安全值），其他是企劃 10/13 回覆的。

- **必填項目**（表裡前 13 項）：每一項都要有，少了會報錯。
- **選填項目**（表裡標「選填」的）：試算表沒有這一列時，匯入用暫定值並提醒一聲，不算錯誤；有這一列就要填能用的值。之後新加的設定都是選填項目，舊的試算表不用補列也能匯入。資料檔（`settings.json`）裡沒有選填項目時，檢查不報錯，遊戲讀檔時用暫定值。

| 項目 | 暫定值 | 意思 | 能填什麼 | 資料檔欄位 |
|---|---|---|---|---|
| 起始手牌 | 4 | 開局每人手上的牌數 | 0 以上的整數 | `startingHand` |
| 起始英鎊 | 10 | 開局每人的英鎊 | 0 以上的整數 | `startingPounds` |
| 起始影響力 | 3 | 開局每人的影響力 | 0 以上的整數 | `startingInfluence` |
| 手牌上限 | 7 | 黑夜結束時超過就棄到這個數（黑夜期間自己挑；沒挑的，下一回合日出時隨機棄） | 1 以上的整數 | `handLimit` |
| 日出抽牌 | 2 | 每回合日出時每人抽幾張 | 0 以上的整數 | `drawPerSunrise` |
| 每輪最多出牌 | 4 | 白晝輪到自己時最多出幾張（也可以不出） | 1 以上的整數 | `maxPlaysPerTurn` |
| 日出提醒秒數 | 60 | 日出的提醒倒數 | 1 以上的整數 | `reminderSeconds.sunrise` |
| 白晝每人提醒秒數 | 60 | 白晝每人各自的提醒倒數 | 1 以上的整數 | `reminderSeconds.day` |
| 黃昏提醒秒數 | 120 | 黃昏的提醒倒數 | 1 以上的整數 | `reminderSeconds.dusk` |
| 黑夜提醒秒數 | 120 | 黑夜的提醒倒數 | 1 以上的整數 | `reminderSeconds.night` |
| 黃昏揭曉倒數秒數 | 3 | 全員送出後倒數幾秒揭曉（超過 60 時遊戲照 60 秒算） | 0 以上的整數 | `duskRevealSeconds` |
| 迷霧門檻 | 30、60、90 | 迷霧值超過這些數時觸發迷霧事件 | 0–100 的整數，由小到大、不重複；用頓號、逗號、斜線或空白隔開 | `fogThresholds` |
| 日落鐘分鐘數 | 75 | 開局（主持端按「開始」）幾分鐘後，那一回合的黑夜結束就進入終局計分 | 1 以上的整數 | `sunsetMinutes` |
| 響應等待秒數（選填） | 5 | 別人出一張牌後，等幾秒讓其他人打出響應卡 | 1 以上的整數 | `responseSeconds` |
| 日出一般事件張數（選填） | 1 | 每回合日出時每桌翻幾張一般事件；0＝不翻 | 0 以上的整數 | `sunriseEvents` |
| 黑夜揭曉倒數秒數（選填） | 3 | 黑夜全員送出後倒數幾秒揭曉 | 0–60 的整數 | `nightRevealSeconds` |
| 豪賭爆掉點數（選填） | 1、2、3 | 豪賭第 1、2、3 層各擲一顆六面骰，擲到這個點數以下（含）就爆 | 3 個 0–6 的整數（0＝那一層不會爆、6＝一定爆） | `gambleBust` |
| 豪賭累積英鎊（選填） | 5、20、30 | 過了第 1、2、3 層時，累積變成多少英鎊（第 3 層就是秘寶） | 3 個 0 以上的整數 | `gamblePounds` |
| 豪賭累積影響力（選填） | 0、1、1 | 過了第 1、2、3 層時，累積變成多少影響力 | 3 個 0 以上的整數 | `gambleInfluence` |
| 豪賭醫藥費（選填） | 2 | 豪賭爆了，累積歸零之外另付的英鎊（不夠就付到 0） | 0 以上的整數 | `gambleMedicalFee` |
| 分贓英鎊（選填） | 6 | 選分贓的人平分這麼多英鎊（捨去；只有 1 人就拿全部） | 0 以上的整數 | `splitPounds` |
| 分贓罪孽（選填） | 1 | 選分贓的人每人記幾點罪孽（分到 0 英鎊也照記） | 0 以上的整數 | `splitSin` |
| 回合上限（選填） | 12 | 到了第幾回合，那一回合的黑夜結束就算分（日落鐘還沒到也一樣；安全上限） | 1 以上的整數 | `maxRounds` |
| 資產英鎊換算（選填） | 5 | 終局時英鎊每幾點換 1 分（捨去） | 1 以上的整數 | `scoreRates.pounds` |
| 資產影響力換算（選填） | 3 | 終局時影響力每幾點換 1 分（捨去） | 1 以上的整數 | `scoreRates.influence` |
| 公共成就分數（選填） | 3 | 議會之聲、齒輪大師各給幾分（同分的都給） | 0 以上的整數 | `achievementPoints` |
| 罪孽扣分換算（選填） | 2 | 終局時罪孽每幾點扣 1 分（捨去） | 1 以上的整數 | `sinPerPenalty` |

提醒倒數到了只提醒，不會自動切換階段。薪水不在這裡，在階層表裡每個階層各填一個。豪賭的三項是照第 1、2、3 層的順序寫三個數，用頓號、逗號、斜線或空白隔開（例如 `5、20、30`），不用由小到大、可以重複；迷霧門檻才要由小到大。

## 階層（roles.csv）

一列一個階層。規則是 6 個，數量不是 6 時檢查會提醒。

| 欄名 | 意思 | 能填什麼 | 空白時 | 資料檔欄位 |
|---|---|---|---|---|
| 編號 | 行動牌與天命的「所屬階層」填這個 | 見共通規則 | 必填 | `id` |
| 名稱 | 階層名稱 | 文字 | 必填 | `name` |
| 薪水 | 日出時每回合領的英鎊 | 0 以上的整數 | 必填 | `salary` |
| 特權1、特權2… | 階層特權，一格一項 | 文字；不夠就加「特權3」欄，以此類推 | 那一格略過 | `privileges`（文字陣列） |
| 使命1、使命2、使命3… | 階層使命，一格一項 | 文字；不夠就加欄 | 那一格略過 | `missions`（文字陣列） |

## 行動牌（actions.csv）

白晝出的牌，分兩種（10/15 定案）：

- **一般牌**：輪到自己時出。
- **響應卡**：別人每出一張牌，其他人有短暫時間可以打出響應卡；先到先算，一次只接一張，時間到就自動繼續。每張響應卡要標明可以回應哪幾類牌，或任何牌都可以。

一列是一種牌，「張數」是牌庫裡有幾張這種牌。牌庫每桌一副共用（10/15 定案）。

| 欄名 | 意思 | 能填什麼 | 空白時 | 資料檔欄位 |
|---|---|---|---|---|
| 編號 | | 見共通規則 | 必填 | `id` |
| 名稱 | 牌名 | 文字 | 必填 | `name` |
| 類型 | 一般牌或響應卡 | 「一般」或「響應」 | 必填 | `kind`（`play`／`response`） |
| 分類 | 這張牌是哪一類；響應卡的「可回應」對照這一欄 | 短文字，例如「交易」「干擾」，名稱自己訂 | 沒有分類（`null`） | `category` |
| 可回應 | 響應卡可以回應哪幾類牌；一般牌不填 | 「分類」欄用到的名稱，好幾個用頓號隔開 | 響應卡：任何牌都能回應（`null`），寫「任何」也一樣；一般牌：一定空白 | `respondsTo`（只有響應卡才有） |
| 所屬階層 | 這張牌屬於哪個階層 | 階層表的編號 | 不屬於任何階層（`null`） | `role` |
| 張數 | 共用牌庫裡有幾張 | 1 以上的整數 | 必填 | `copies` |
| 英鎊成本 | 出這張牌要付的英鎊 | 0 以上的整數 | 0 | `cost.pounds` |
| 影響力成本 | 出這張牌要付的影響力 | 0 以上的整數 | 0 | `cost.influence` |
| 齒輪 | 齒輪連鎖用的標記 | 短文字 | 沒有標記（`null`） | `gear` |
| 效果 | 見「效果的寫法」 | | 沒有效果 | `effects` |
| 牌面文字 | 牌上寫的、玩家看到的文字 | 文字 | 必填 | `text` |

- 一般牌、響應卡都可以填「分類」。同一類的名稱要寫得一模一樣，「可回應」才對得上；寫了沒有任何牌用的分類，檢查時會提醒。
- 響應卡的效果用同一種寫法，`@自己` 是打出響應卡的人；另外可以用 `@出牌者`（被回應的那張牌是誰出的）和 `抵銷`（那張牌的效果不發生）。響應卡的「偷」寫 `@出牌者`，偷的人是打出響應卡的人。
- 遊戲裡「偷」怎麼算（M7）：拿走的量＝牌上的數量與對方目前的數量取小的，對方減這麼多、偷的人加這麼多，總量不變。齒輪連鎖 4 級時數量加倍（「對別人的扣減也加倍」）；2 級的「給自己的加倍」不套在偷上（工程暫定）；響應卡不吃連鎖加成；被抵銷的牌不偷。響應卡的偷只能寫 `@出牌者`（寫 `@指定` 檢查時就報錯）；其他效果用 `@指定` 的響應卡這一版還是會被退回。
- 遊戲裡響應卡怎麼算（M5b）：別人打出一般牌後有「響應等待秒數」可以打；只能回應一般牌（響應卡不能被響應）、不能回應自己出的牌；一張牌最多被響應一次，先到先算。響應卡要付成本，不算出牌數，也不影響齒輪連鎖；分類是「犯罪」或「破壞」的響應卡，打的人一樣記罪孽。不是抵銷時，被回應的牌先照常結算，再結算響應卡；響應卡的數字不吃齒輪連鎖的加成。用到 `@指定` 的響應卡這一版還不能打（打出去會被退回），要用請先跟工程說。

一列一張。法案不要放這裡，請放法案表。

| 欄名 | 意思 | 能填什麼 | 空白時 | 資料檔欄位 |

| 門檻 | 迷霧事件在迷霧值超過多少時觸發 | 0–100 的整數，要是設定裡的迷霧門檻之一 | 一般事件一定空白；迷霧事件必填 | `threshold` |

遊戲裡事件怎麼算（M7）：

- **一般事件**（企劃 10/15 回「照建議」，暫定）：每回合日出領薪、抽牌之後，每桌從自己那一疊一般事件翻最上面一張（張數照設定的「日出一般事件張數」，預設 1），對那一桌結算效果，翻到的事件在日出與白晝一直顯示給全桌看。第 1 回合也翻。那一疊是第一次用時把全部一般事件隨機洗成的（不照年代排），翻完就把全部一般事件重洗再用。
- **迷霧事件**：迷霧值「大於」門檻才算越過（剛好 30 不算）；每個門檻每場只在第一次越過時觸發，降回門檻以下再升上來不再觸發；一次越過好幾個門檻時由小到大處理。造成越過的那張牌（含它的連鎖加成與響應）、那張法案或那張一般事件整個結算完，接著就結算迷霧事件；迷霧事件的效果又讓迷霧越過下一個門檻時，接著觸發下一個。設定的門檻沒有對應的迷霧事件時，只記下「越過了」，沒有效果。
- 對象：`@全體` 是該桌入座的人，`@階層編號` 打到坐那個階層的人（沒人坐就打空）；`@指定` 這一版不結算（略過那一項，畫面寫一行提示），要用請先跟工程說。整筆標成 todo 的事件照樣翻、照樣顯示，效果不結算。英鎊、影響力不會扣到 0 以下；抽牌、棄牌照白晝的做法（棄牌隨機挑）。

## 隱藏天命（destinies.csv）

一列一張。每人發 1 張（10/15 定案），一桌六人，至少要 6 張才發得完。

| 欄名 | 意思 | 能填什麼 | 空白時 | 資料檔欄位 |
|---|---|---|---|---|
| 編號 | | 見共通規則 | 必填 | `id` |
| 所屬階層 | 這張天命屬於哪個階層 | 階層表的編號 | 不屬於特定階層（`null`） | `role` |
| 天命文字 | 玩家手機上看到的天命 | 文字 | 必填 | `text` |
| 計分條件 | 怎樣算達成（玩家看的說明） | 文字 | 必填 | `score.text` |
| 判定（M9 新增，選填欄） | 終局時程式怎麼判定達成，寫法見下表 | 一格一個條件 | 終局時由主持端逐人勾「達成／沒達成」（`null`） | `check` |
| 分數 | 達成得幾分 | 0 以上的整數 | 還沒定（`null`） | `score.points` |

- 「判定」是選填欄：舊的試算表沒有這一欄也能匯入（資料檔就沒有 `check`，等於每張都空白）。有這一欄時，空白的寫成 `null`。
- 開局發天命時（企劃 10/15）：自己階層的天命裡，「判定」提到這一桌沒人坐的階層的（目前只有「多於 rN」）先不發，從同階層其他張挑；這樣挑完沒得挑，就照原本的挑法發（計分時照「沒人坐算達成」）。例：沒人坐 r5 時，r4 只會拿到「英鎊多於 r5」以外的那張。
- 天命達成得「分數」那麼多分，沒達成 0 分。終局時公開每個人的天命與是否達成。

「判定」的寫法（比較符號是 `>`、`>=`、`<`、`<=`；全形字、空白多寡都可以；法案用頓號或逗號隔開）：

| 寫法 | 什麼時候算達成 | 資料檔的 `check` |
|---|---|---|
| `法案通過 b06` | 終局時 b06 是通過的（照每張法案最後一次的表決結果） | `{ "kind": "bills", "passed": true, "bills": ["b06"], "atLeast": 1 }` |
| `法案沒通過 b05` | 終局時 b05 不是通過的；**整場沒被表決的也算沒通過** | `{ "kind": "bills", "passed": false, "bills": ["b05"], "atLeast": 1 }` |
| `法案都沒通過 b01、b06` | 列出的每一張都沒通過（沒被表決的算沒通過）；`法案都通過 …` 同理 | `{ "kind": "bills", "passed": false, "bills": ["b01", "b06"], "atLeast": 2 }` |
| `法案通過至少 2：b01、b06、b02、b03` | 列出的法案裡至少通過 2 張；`法案沒通過至少 N：…` 同理 | `{ "kind": "bills", "passed": true, "bills": ["b01", "b06", "b02", "b03"], "atLeast": 2 }` |
| `迷霧 < 60`、`迷霧 >= 60` | 終局時的迷霧值 | `{ "kind": "compare", "what": "fog", "op": "<", "value": 60 }` |
| `迷霧最高 > 90` | 本場迷霧的最高值 | `{ "kind": "compare", "what": "fogMax", "op": ">", "value": 90 }` |
| `英鎊最多`、`影響力最多`、`手牌最多` | 終局時全桌比，同分（同數）都算 | `{ "kind": "most", "what": "pounds" }`（`influence`、`hand`） |
| `英鎊 >= 40`、`影響力 >= N`、`手牌 >= N` | 終局時自己的數量 | `{ "kind": "compare", "what": "pounds", "op": ">=", "value": 40 }` |
| `英鎊多於 r5`（`影響力多於 rN`、`手牌多於 rN` 同理） | 比坐那個階層的其他人多（一樣多不算）；那一桌沒有別人坐該階層算達成 | `{ "kind": "moreThan", "what": "pounds", "role": "r5" }` |

- 法案編號要是法案表有的、階層編號要是階層表有的；看不懂的寫法匯入時照原文留著，檢查報錯（不會默默變成空白）。「多於」寫的是這張天命自己的階層時（拿到的人就坐那個階層，沒有別人可以比，一定算達成）檢查會提醒一聲。
- 天命文字最多 500 個字（終局時會寫進公開的結算）。
- 「終局時」是最後一回合黑夜揭曉之後、主持端按「下一階段」那一刻：黑夜的變化已經算進去。
- 手牌的判定（`手牌最多`、`手牌 >= N` 這類比較、`手牌多於 rN`）**先套手牌上限再比**：每個人的手牌張數和設定的「手牌上限」（`handLimit`）取較小的（企劃 10/16 定案）。終局不做下一回合日出的棄牌，但最後一夜也算黑夜結束，最後一回合多抽的牌不算數；只用在判定，不真的棄牌。例：上限 7 時，手牌 10 張與 8 張的人都算 7 張，`手牌最多` 兩人都達成；`手牌 >= 8` 誰都達不到。

## 資料檔長相（給工程）

每個檔是 UTF-8 的 JSON；`settings.json` 是一個物件，其他六個是陣列。行動牌的一筆長這樣：

```json
{
  "id": "a02",
  "name": "範例行動牌二",
  "kind": "play",
  "category": "範例分類甲",
  "role": "r1",
  "copies": 1,
  "cost": { "pounds": 3, "influence": 1 },
  "gear": "範例齒輪",
  "effects": [
    { "op": "influence", "target": "self", "amount": 2 },
    { "op": "fog", "amount": 3 },
    { "op": "discard", "target": "chosen", "amount": 1 }
  ],
  "text": "範例：自己拿 2 影響力，迷霧加 3，指定一人棄 1 張牌。"
}
```

- 可空的欄位一律寫出來，沒有就是 `null`（天命的 `check` 例外：試算表有「判定」欄才寫出來，見「隱藏天命」）。`threshold` 只有迷霧事件才有；`respondsTo` 只有響應卡才有；`todo`（`true`）與 `todoText`（看不懂的原文）只有效果還沒換算時才有。
- `kind` 只有 `play`（一般牌）、`response`（響應卡）。響應卡的 `respondsTo` 是 `null`（任何牌都能回應）或分類名稱的陣列，例如 `["範例分類甲"]`：別人出的牌 `category` 在陣列裡才能回應。
- `op` 只有 `pounds`、`influence`、`fog`、`draw`、`discard`、`cancel`、`steal`；`target` 只有 `self`、`all`、`others`、`chosen`、`role`、`originalPlayer`。`fog` 不寫 `target`；`cancel` 只有 `op`；`target` 是 `role` 時另寫 `role`（階層編號），例如 `{ "op": "pounds", "target": "role", "role": "r2", "amount": 4 }`。`cancel` 與 `originalPlayer` 只會出現在響應卡。`steal` 另寫 `resource`（`pounds` 或 `influence`），`target` 只能是 `chosen` 或 `originalPlayer`，`amount` 是 1 以上的整數，只會出現在行動牌，例如 `{ "op": "steal", "resource": "pounds", "target": "chosen", "amount": 3 }`。
- JSON 不能寫註解，`settings.json` 每一項的意思看上面的設定表。選填的設定在 `settings.json` 裡一樣寫出來（匯入時補上暫定值），遊戲讀到的設定永遠是齊的。
- 格式定義與檢查在 `play/js/data.js`。

## 檢查的訊息怎麼讀

一行一筆，例如：

```
錯誤｜actions.json｜a01（actions.csv 第 2 列）｜copies（張數）｜要是 1 以上的整數，現在是 0
```

依序是：等級、資料檔、編號（沒有編號時寫「第幾筆」；匯入時括號裡是試算表的列號，欄名那列算第 1 列）、欄位（括號裡是試算表的欄名）、原因。有錯誤時指令以非 0 結束，`npm test` 也不會通過；只有警告時照樣通過。

常見的錯誤：

| 訊息裡有 | 意思 | 怎麼改 |
|---|---|---|
| `少了欄位「…」` | 第一列缺了樣板上的欄名；這次一個檔都沒寫入 | 從樣板複製欄名，字不要改 |
| `不是 UTF-8 編碼` | 匯出時選錯格式 | Excel 選「CSV UTF-8」；Google 試算表直接下載 CSV |
| `引號沒有關閉` | 某一格的引號只有開頭沒有結尾，多半是手改 CSV 造成 | 用試算表打開再匯出一次 |
| `略過 …：認不出是哪一種資料` | 檔名對不上 | 照「檔名」一節改名 |
| `必填，只能用英文字母、數字、- 和 _` | 編號空白，或用了中文、空格 | 改成像 `a01` 的編號 |
| `和第 N 筆重複` | 同一張表有兩列編號相同 | 改掉其中一個 |
| `要是 1 以上的整數，現在是「兩」` | 數字欄填了文字、小數，或超出範圍 | 填範圍內的整數 |
| `找不到階層編號` | 所屬階層，或效果的 `@階層編號`，填了階層表沒有的編號 | 填階層表的編號；所屬階層也可以留空 |
| `必填，要是不空白的文字` | 名稱、牌面文字這類必填欄空白 | 補上 |
| `事件沒有出牌的人`、`法案沒有出牌的人` | 事件或法案的效果用了 `@自己` 或 `@其他人` | 改成 `@全體`、`@指定` 或 `@階層編號` |
| `只能用在響應卡` | `抵銷` 或 `@出牌者` 寫在一般牌、法案或事件 | 拿掉或換別的對象；真的是響應卡就把類型改成響應 |
| `偷（steal）只能用在行動牌` | 法案或事件的效果寫了「偷」 | 拿掉，或改成英鎊、影響力的加減 |
| `一般牌的偷只能對 @指定`、`響應卡的偷只能對 @出牌者` | 「偷」沒寫對象，或寫了別的對象（`@自己`、`@全體`、`@其他人`、`@階層編號`，或響應卡寫了 `@指定`） | 一般牌寫 `@指定`，響應卡寫 `@出牌者` |
| `偷的 amount 要是 1 以上的整數` | 「偷」的數量是 0、負數或小數 | 例如 `偷英鎊3@指定` |
| `只能是 play（一般牌）或 response（響應卡）` | 行動牌的類型空白或填錯 | 填「一般」或「響應」 |
| `一般牌不填可回應` | 一般牌的「可回應」有填 | 清掉，或把類型改成響應 |
| `迷霧事件一定要有門檻` | 類型是迷霧，門檻空白 | 填門檻，例如 30 |
| `一般事件不填門檻` | 類型是一般卻填了門檻 | 清掉門檻，或把類型改成迷霧 |
| `只能是 deck（一般事件）或 fog（迷霧門檻事件）` | 類型填錯 | 填「一般」或「迷霧」；法案請搬到法案表 |
| `要由小到大排、不可重複` | 設定的迷霧門檻順序不對 | 例如 `30、60、90` |
| `要是 3 個 …的整數，照順序寫` | 豪賭的設定不是剛好 3 個數，或超出範圍 | 照第 1、2、3 層寫三個數，例如 `5、20、30` |
| `現在沒有這一欄`（設定） | 設定少了一項必填項目 | 從樣板補上那一列 |
| `只能是 sunrise（日出）／day（白晝）…` | 教學提示的階段填錯 | 填「日出」「白晝」「黃昏」「黑夜」 |
| `看不懂「…」：看不懂這個寫法` | 天命的「判定」不是上面任何一種寫法（例如 `英鎊 = 40`、`手牌 ≥ 3`） | 照「隱藏天命」的判定寫法表改；不能自動判定就留空白，終局時由主持端勾 |
| `看不懂「…」：好幾張法案要寫「法案都通過」…` | 「法案通過」「法案沒通過」後面列了好幾張 | 寫成 `法案都沒通過 b01、b06` 或 `法案通過至少 2：b01、b06、b02` |
| `看不懂「…」：「都」和「至少 N：」只能擇一` | 同時寫了「都」和「至少」 | 留一個 |
| `看不懂「…」：法案編號只能用英文字母…`、`「多於」後面要寫階層編號` | 判定裡寫了法案名稱或階層名稱 | 改寫編號，例如 `b06`、`r5` |
| `找不到法案編號` | 判定寫了法案表沒有的編號 | 填法案表的編號 |
| `判定的「至少」要是 1–N 的整數` | 「至少」的張數比列出的法案還多，或是 0 | 改小，或多列幾張法案 |
| `判定的法案重複了` | 同一張法案列了兩次 | 拿掉重複的 |
| `最多 500 個字` | 天命文字太長 | 縮短 |

警告（不擋匯入）：

| 訊息裡有 | 意思 |
|---|---|
| `效果還沒換算成結構（todo）` | 效果欄有看不懂的寫法，這筆的效果先不結算；確定做法後改成上面的格式 |
| `沒有任何效果` | 效果欄空白；故意的就不用管 |
| `設定的迷霧門檻（…）裡沒有 N` | 迷霧事件的門檻不是設定裡的門檻之一，永遠不會觸發 |
| `沒有任何行動牌的分類是「…」` | 響應卡的「可回應」寫了沒有任何牌用的分類，多半是打錯字；這一項回應不到任何牌 |
| `規則是 6 個階層` | 階層表不是 6 列 |
| `不認得的欄位` | 資料檔多了不認得的欄位，多半是手改資料檔時打錯字 |
| `提醒：…這幾欄不會匯入` | 試算表有樣板以外的欄，例如自己加的說明欄 |
| `不認得的設定項目` | 設定表的項目名稱打錯，那一列沒有匯入 |
| `提醒：…沒有「…」這一列，用預設值` | 設定少了選填項目，用暫定值；要改就補上那一列 |
| `「多於 rN」比的是這張天命自己的階層` | 天命的「判定」寫「多於」自己的階層，拿到的人一定算達成；多半是階層填錯 |
| `提醒：沒有教學提示（tutorial.csv）` | 這次沒交教學提示；沿用現有的，或寫入空的（遊戲不顯示提示） |
