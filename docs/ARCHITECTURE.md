# 架構決定：多人連線版

適用範圍：`play/`（「一日英國人：女皇陛下萬歲！」的遊戲網頁）。狀態：已採用，目前做到單場的終局與計分（M5：輪流出牌、成本與效果、齒輪連鎖、響應卡；M6：法案暗標投票、揭曉與結算；M7：日出一般事件、迷霧事件、「偷」；M8：黑夜的豪賭、分贓、睡覺與手牌上限；M9：日落鐘、單場計分、結算畫面；兩場制還沒做）。

## 一句話

靜態網頁（原生 HTML＋CSS＋ES modules，不用框架、不用打包工具）＋ Firebase Realtime Database 當唯一的狀態來源＋匿名登入。我方沒有自己的伺服器：階段推進與計算由主持端裝置做完後寫入資料庫，其他人只訂閱。

## 條件

- 活動當天 6 桌 × 6 人＋工作人員，約 51 台裝置，單場 90 分鐘。
- 用免費方案（Firebase Spark）：同時連線上限 100、不綁卡、資料庫放新加坡。免費方案沒有雲端函式。
- 網頁程式、字型、圖片全部自行託管，不引用第三方內容傳遞網路。

## 選了什麼、為什麼

- **原生網頁，不打包。** 頁面小（目前載入的檔案壓縮後約 127 KB），部署就是複製檔案，手機上出問題可以直接看原始碼。
- **唯一的例外是官方 Firebase JS SDK**（固定版本、自行託管）。斷線重連、離線期間的寫入排隊、登入憑證自動更新，正好是現場最容易出事的地方，不自己重寫。
- **本機用模擬器開發與測試。** `demo-` 開頭的專案代號完全離線、不需要帳號。正式專案只是換一組設定（見下方「環境」），測試直接跑同一份 `js/store.js`，不寫第二套假後端。

## 環境

- `js/config.js` 有兩組設定：本機模擬器（`demo-one-day-briton`）與正式專案（免費方案、資料庫在新加坡，只開匿名登入與 Realtime Database）。網址帶 `?env=emu`／`?env=prod` 就照參數；沒帶的話，本機（`localhost`、`127.0.0.1`、`::1`）用模擬器，其他主機用正式專案。選擇規則是純函式，有單元測試。
- 靜態檔放 GitHub Pages 的 `/one-day-briton/play/`，不用 Firebase Hosting。
- 正式專案的設定值（`apiKey` 等）是公開的識別碼，跟網頁一起公開；擋人的是安全規則。
- 安全規則目前在 Firebase 主控台手動發布，內容以 repo 的 `database.rules.json` 為唯一來源：先改這個檔、跑過 `npm run test:sync`，再整份貼到主控台發布；不在主控台上直接改。

## 放棄了什麼

- **自己寫即時伺服器**：免費主機會休眠或重啟，場中一斷全場停。
- **Cloudflare Workers＋Durable Objects**：伺服器與重連協定都要自己寫。
- **Firestore**：以讀取次數計費，每台裝置每收到一次變動都算讀取，一場活動的監聽量會超過每日免費額度。

## 資料模型

房＝一個場次；桌＝房內第 1–6 桌，各自有回合與階段。

```
/rooms/{code}                     code＝6 碼大寫英數，去掉 0 O 1 I L
  /meta               { hostUid, createdAt, tableCount }  建立後不可改；hostUid＝開房的人
  /tables/{n}         { round, phase, fog, updatedAt }    n＝1–6；round 從 1 起；fog 0–100；phase 多一個 end（終局，之後不能再改）
  /players/{uid}      { name, table, joinedAt }           uid＝匿名登入的身分
  /hosts/{uid}        true                                被核准的其他主持端（不含開房的人）
  /hostRequests/{uid} { requestedAt }                     想當主持端的裝置自己寫入，等核准
  /presence/{uid}     true                                連著的時候才有；斷線由伺服器代為移除
  /games/{n}          { startedAt, seats, deckCount, discardCount, version, … }  該桌的局面，開局時建立
    /seats/{uid}      { order, role, pounds, influence, handCount, sin, aligned }  order＝座位 0–5（順時針）；sin、aligned 沒有＝0；sin 含黑夜分贓記的
    /version          整數                                每筆改到這一桌局面的寫入都要「新＝舊＋1」，開局寫 1
    /startOrder       0–5                                 第 1 回合的起始座位，沒設＝0
    /turn             { round, index, plays, gear, level } 白晝輪到第幾位、他這一輪出了幾張、上一張的齒輪與級數
    /fogMax、/fogFired、/fogPending                         本場迷霧最高值、已觸發的門檻、新越過還沒處理的門檻
    /lastSeq/{uid}    整數                                已處理過的請求序號
    /pending          { id, by, seq, card, level, target, chainTarget, openedAt, seconds }  接下了、等著響應的一般牌（見「響應卡」），沒有就不存在
    /log/{id}         { round, by, card, level, target, chainTarget, response, canceled, at }  出牌紀錄（打出的牌本來就公開）
    /dusk             { round, bill, openedAt, submitted, revealAt, result }  這一回合的黃昏（見「黃昏投票」）；bill 沒有＝議會休會
                      result＝{ yes, no, passed, votes: { uid: { side, bid } } }，揭曉後才有
    /duskLog/{round}  { bill, yes, no, passed, votes }    揭曉後的公開紀錄，一回合一筆
    /bills/{法案編號} 'passed' | 'failed'                 每張法案最後一次的結果（天命判定用）
    /eventLog/{i}     { round, phase, event, kind, threshold, skipped }  公開的事件紀錄（見「事件」），i 從 0 連號，寫了不能改不能刪
    /night            { round, openedAt, submitted, revealAt, result }  這一回合的黑夜（見「黑夜」）；result＝{ players: { uid: 結果 } }，揭曉後才有
    /nightLog/{round} { players: { uid: { choice, tiers, rolls, bust, pounds, influence, sin } } }  揭曉後的公開紀錄，一回合一筆
    /endAfterRound    整數                                主持端按「這回合結束後算分」時寫目前的回合；取消＝刪掉（見「終局與計分」）
    /final            { round, endedAt, reason, scores: { uid: 分數 } }  終局那一筆寫入，之後只有天命的勾選、總分、名次能改
  /deals/{n}          整數                                已處理過日出的回合數
/private/{code}/{uid} { table, hand: [牌編號…], destiny, notice }  本人與主持端可讀，見下一節
/hostOnly/{code}/{n}  { deck: [牌編號…], discard: [牌編號…], billDeck: [法案編號…], eventDeck: [事件編號…] }  只有主持端可讀寫
/requests/{code}/{uid} { seq, type, card, target, chainTarget, pending, at }  玩家自己寫，本人與主持端可讀
/votes/{code}/{uid}   { table, round, side, bid, seq, at }  黃昏的票，玩家自己寫，本人與主持端可讀
/nights/{code}/{uid}  { table, round, choice, tiers, seq, at }  黑夜的選擇，玩家自己寫，本人與主持端可讀
/discards/{code}/{uid} { table, round, cards: [牌編號…], seq, at }  手牌超過上限時挑的棄牌，玩家自己寫，本人與主持端可讀
```

- 階段：`sunrise` 日出 → `day` 白晝 → `dusk` 黃昏 → `night` 黑夜 → 下一回合的日出；黑夜揭曉後該算分時改進 `end` 終局（M9，見「終局與計分」），終局後不再推進。
- 推進一律用交易（transaction），而且帶著「我以為現在是第幾回合、哪個階段」；資料庫現況不一樣就不動。連點兩下或兩台主持端同時按，都只會前進一步。
- 主持端＝開房的人，加上主持名單（`hosts`）上的人。備援裝置在首頁用房號「以主持端進入」留下申請，現任主持端核對兩邊畫面上相同的 4 碼確認碼（由申請者的 uid 算出）後核准；核准是一次寫入（加進名單＋清掉申請）。名單上的人也能核准別人，所以「全場一台主持機＋備援機」與「每桌帶玩員各自操作」都適用。
- 上線狀態不定時回報、不寫時間戳：每次連上都先請伺服器登記「斷線時移除」再寫入 `presence`，離開房間時自己移除。自己的連線狀態另外看 `.info/connected`，斷線時畫面頂端提示，不會把人送回首頁。
- 迷霧值 0–100，超過 30／60／90 觸發迷霧事件（M7，見「事件」）。
- 開局（主持端每桌一個「開始」鈕）：`players` 裡 `table＝n` 的人入座，0 人或超過 6 人不能開，少於 3 人可以開但畫面提醒。六個階層隨機分給入座的人、不重複，座位順序也隨機；每人起始英鎊、影響力、手牌照 `settings.json`；隱藏天命 1 張，從自己階層的天命隨機挑，沒有就從不屬於任何階層的挑，再沒有就沒有，同桌不發重複的。牌庫＝所有行動牌（一般牌與響應卡）依張數展開後洗牌，每桌一副。`startedAt` 是伺服器時間，只能寫一次，日落鐘之後從這裡算。
- 日出：每人領自己階層的薪水、抽 `drawPerSunrise` 張；牌庫不夠時先抽完剩下的，再把棄牌堆洗回成新牌庫接著抽，兩邊都空就不抽。第 2 回合起，同一筆寫入的最前面先套用手牌上限（上一回合黑夜挑的棄牌，M8，見「黑夜」），棄的牌進棄牌堆之後才領薪抽牌。開局的同一筆寫入接著做第 1 回合日出（企劃 10/15 確認；`js/game.js` 的 `FIRST_SUNRISE_PAYS`）。領薪抽牌之後，同一筆寫入接著翻這一回合的一般事件（M7，見「事件」）。
- 開局與每回合日出都是一筆多路徑寫入（`games`（含 `eventLog`）、`deals`、各人的 `private`、`hostOnly` 一起），由主持端算好再送出。防重複靠規則：`deals/{n}` 只能往上加、而且要等於該桌目前的回合；開局另外靠 `startedAt` 只能寫一次。兩台主持端同時開局或同時發同一回合，後到的那筆整筆被拒；被拒的一方等伺服器傳來現況（本機快取可能還是舊的），看到已經發過就不再發。
- 誰觸發日出發牌：主持端按「下一階段」從黑夜進到下一回合日出、而且是自己那筆交易成功的，接著自動發牌。任何主持端看到已開局、在日出、`deals/{n}` 小於目前回合時，畫面顯示「日出還沒發牌」與「補發」鈕（主持機在推進與發牌之間掛掉時，備援機用它補）。開局前、日出還沒發牌時，「下一階段」停用（畫面擋，規則不擋）。
- 推進用的交易只動 `tables/{n}`，局面在 `games/{n}`，兩者互不覆蓋。
- 開局後才加入該桌的人不入座：玩家畫面說明「本桌已開局」，主持端名單標「未入座」；不做中途入座。
- 隨機一律用 `crypto.getRandomValues`（Fisher–Yates，取餘數前丟掉尾段，不偏）；`js/game.js` 的純函式接受注入的亂數來源，測試用固定種子。網址帶 `?seed=<整數>` 時主持端改用固定種子（洗牌、隨機棄牌），只有模擬器認這個參數，正式專案一律忽略（`js/config.js` 的 `selectSeed`，有單元測試）。

### 白晝出牌（M5a）

- 輪流：白晝依座位順時針，一人一輪最多出 `maxPlaysPerTurn`（4）張，也可以不出（「結束這一輪」）；出滿自動換下一位。第 1 回合從 `startOrder`（主持端在第一張牌之前可以指定，沒設是座位 0）開始，之後每回合起始往下一位移。`turn.round` 不是目前的回合，就當這一回合的白晝還沒開始（第一位、0 張）。所有人都輪完＝白晝結束；主持端照舊手動按「下一階段」，沒輪完也能按，畫面提醒「還有 n 人沒出完」。每人 60 秒的提醒倒數只顯示，從各裝置看到輪到這個人的那一刻算起，不會自動換人。
- 請求：玩家把「我要出這張牌」（`type: play`，帶 `card`，要指定對象的牌帶 `target`，3 級連鎖帶 `chainTarget`）、「結束這一輪」（`type: pass`）或「我要響應」（`type: respond`，見下一節）寫進自己的 `/requests/{code}/{uid}`，序號 `seq` 一筆比一筆大，`at` 由伺服器填。每人只有一個請求節點，畫面在主持端處理完之前不讓再送；沒處理就被蓋掉的舊請求不會被結算。玩家裝置不算任何結果。
- 結算：開著主持畫面的每台主持端都盯著入座玩家的請求（`store.js` 的 `startSettling`，逐人訂閱 `requests/{code}/{uid}`），看到 `seq` 大於該桌 `lastSeq/{uid}` 的就讀局面、手牌、牌庫，交給 `game.js` 的 `processRequest` 算，再一筆多路徑寫入（局面、該桌迷霧值、有變的手牌、牌庫與棄牌堆）。不合法的請求只寫 `lastSeq` 與本人的 `notice`（`{ seq, reason }`，原因的說明在 `game.js` 的 `REJECT_REASONS`），局面不動。
- 一張一般牌的順序：檢查（白晝、輪到他、出牌數未滿、牌在手上、不是響應卡、不是 `todo`、英鎊與影響力付得起、要的對象有給且合法）→ 付成本 → 算齒輪級數 →（響應窗口）→ 依序套用效果（加上級數加成）→ 牌進棄牌堆 → 記罪孽、寫紀錄、更新輪次。前半是 `acceptPlay`（回傳已付成本、牌已離開手牌的局面，與待結算的 `pending`＝`{ by, seq, card, level, target, chainTarget }`），後半是 `resolvePlay`；兩步之間是響應窗口（下一節），兩步之間的局面與 `pending` 都是純資料，存進資料庫再讀出來接著算，結果一樣。`settings.responseSeconds` 是 0 時不開窗口，兩步在同一筆寫入完成（M5a 的做法）。
- 效果：英鎊、影響力夾在 0 以上；抽牌沿用日出的 `draw`（牌庫不夠洗回棄牌堆）；棄牌由主持端亂數從手牌隨機挑，不夠就全棄；迷霧用 `advanceFog`、門檻取 `settings.fogThresholds`，新越過的門檻依序放進 `fogPending`，在同一筆結算的最後處理迷霧事件（M7，見「事件」）。偷（M7）：拿走的量＝牌上的數量（4 級連鎖加倍）與對方目前的數量取小的，對方減、出牌的人加，總量不變。對象：`self` 出牌者、`all` 該桌入座的人、`others` 其他入座的人、`chosen` 請求裡的 `target`（同桌另一位入座的人，不能指定自己）、`role` 坐該階層的人（沒人坐就打空）。
- 齒輪連鎖：同一人同一輪內接著打出、齒輪相同的牌，第 n 張是 n 級，沒有齒輪或不同就從 1 級算。2 級：給出牌者自己的英鎊、影響力正數加倍（`@全體` 裡自己那一份也算）；3 級：照常結算，另外出牌者抽 2 張、`chainTarget`（同桌另一位）隨機棄 1 張；4 級：英鎊、影響力、抽牌、棄牌的數量全部加倍，含對別人的扣減，成本與迷霧不變。玩家畫面送出前就顯示「這張會是 n 級連鎖」，3 級要選人。
- 罪孽：出了分類是「犯罪」或「破壞」的牌，出牌者 `sin`＋1（M9 計分用）。
- 防兩台主持端互蓋：每筆改到局面的寫入（開局、日出、結算、指定起始玩家）都帶 `version＝讀到的＋1`，規則只收剛好＋1 的。兩台主持端同時結算同一筆請求，後到的整筆被拒；被拒的一方等伺服器的現況，看到 `lastSeq` 已到就放手，局面被別的寫入改過就重讀重算（最多 3 次），都不是就報錯。主持端先讀局面（`version`）再讀手牌與牌庫，中間有別的寫入時這次的寫入一定被拒，不會把新的手牌配上舊的局面寫回去。
- 推進與結算同時發生：推進的交易只動 `tables/{n}`；結算有迷霧效果時也寫 `tables/{n}/fog`，交易會因此重跑一次，迷霧值不會被蓋掉。規則不檢查結算時的階段：主持端在白晝最後一刻收下的請求，寫入可能在黃昏才到，照樣只算一次；下一回合輪次自然重來。

### 響應卡（M5b）

- 口徑（企劃 10/15 第 10 題與 M5 定案、企劃 10/15 對被抵銷的牌的暫定，加上工程暫定）：別人每打出一張**一般牌**，同桌其他入座的人有 `settings.responseSeconds` 秒（目前 5）可以打出**一張響應卡**；先到先算（以伺服器收到的時間為準），一張牌最多被響應一次，時間到沒人響應就照常結算。響應卡要付成本；`respondsTo` 是可回應的分類，`null`＝任何一般牌；不能回應自己出的牌；響應卡本身不會開窗口；響應卡不算出牌數，也不影響任何人的齒輪連鎖；分類是「犯罪」或「破壞」的響應卡，響應者記 1 點罪孽。要指定對象（`@指定`）的響應卡這一版還不能打（請求不帶對象），會被退回。
- 接下（一筆寫入）：`version＋1`、出牌者的 `lastSeq`、扣成本、手牌拿掉那張、寫 `games/{n}/pending`（`acceptPlay` 的 `pending` 加上主持端產生的 push key `id`、伺服器時間 `openedAt`、當下的 `responseSeconds` 為 `seconds`）；輪次與棄牌堆不動，那張牌這時只在 `pending` 裡。**窗口一律開**，不看有沒有人拿著用得上的響應卡（主持端看得到手牌，跳過等於洩漏「沒人有」）。`responseSeconds` 是 0 時不開窗口。
- 響應：同桌其他人把 `{ type: 'respond', card, pending: <pending.id> }` 寫進自己的請求節點，`at` 由伺服器填，規則要求剛好等於伺服器時間（玩家不能自己寫時間）。合法的條件照順序（`game.js` 的 `acceptResponse`）：有 `pending`、`id` 對得上、`at ≤ openedAt + seconds×1000`、有座位、不是自己出的、牌在手上、是響應卡、不是 `todo`、分類對得上、不用指定對象、付得起。不合法的寫該人的 `lastSeq` 與 `notice`（`version＋1`），`pending` 不動；新的原因代碼與說明在 `REJECT_REASONS`。
- 先到先算：主持端一看到新的響應就整桌交給 `settleWindow`：從伺服器重讀整房的請求，交給 `settlePending`，在合法的響應裡取伺服器時間 `at` 最早的那筆（同時間比 uid 字串），不用等時間到；同一批裡其他的響應一起退回（合法但晚一步的原因是 `beaten`，「別人先響應了這張牌」）。
- 時間到：主持端用 `.info/serverTimeOffset` 把本機時間換算成伺服器時間，到了 `openedAt + seconds×1000 + 1000`（1 秒緩衝，讓截止前送出、還在路上的響應趕得上，`game.js` 的 `responseSettleAt`）由計時器叫醒，**先記下時間、再從伺服器重讀整房的請求**：有 `at` 在截止前的合法響應就照響應結算，沒有就照常結算。Firebase 的 `get` 遇到涵蓋那個路徑的訂閱會直接回快取，所以自動結算逐人訂閱 `requests/{code}/{uid}`、不在整房的 `requests/{code}` 掛訂閱，整房的讀取才會真的問伺服器；主持端斷線時，這次讀取會等連回來才完成，不會拿斷線前的快取當作「沒人響應」。
- 結算（一筆寫入）：`version＋1`、刪 `pending`、套效果、原牌與響應卡依序進棄牌堆、響應者扣成本、手牌拿掉那張、寫他的 `lastSeq`、罪孽、輪次、出牌紀錄（編號沿用 `pending.id`；記 `chainTarget`，有響應記 `response { by, card }`，抵銷另記 `canceled: true`）。順序（工程暫定）：不是抵銷 → 原牌照常結算（含級數加成），**之後**才結算響應卡的效果（`@出牌者`＝原出牌者、`@自己`＝響應者，響應卡不吃級數加成）；抵銷 → 原牌的效果與級數加成（含 3 級的抽 2、指定棄 1）都不結算，成本照付、仍算出了一張、犯罪或破壞照記罪孽、進棄牌堆，連鎖斷在這裡（`turn` 不留齒輪、級數 0，下一張從 1 級重算），抵銷卡上其他的效果照常結算。
- 窗口中：任何人的出牌與結束這一輪都先不處理、也不退回（`processRequest` 回 `deferred`），等 `pending` 結算完（`version` 變了）再照 M5a 處理；沒有 `pending` 時收到響應 → 退回（`no-pending`）。出牌者的畫面寫「等其他人響應 n 秒」，出牌與「結束這一輪」停用；主持端該桌顯示待響應的牌與倒數，「下一階段」停用並寫原因（畫面擋，規則不擋）；第 1 回合的起始玩家在第一張牌等響應時也不能改（規則與 `store.js` 都擋）。
- 多台主持端：看到響應或時間到時都會做，靠 `version` 只成一筆，被拒的一方等局面變了再重讀重算（沿用 M5a）。沒有主持端在線時 `pending` 留著，下一台主持端連上、看到過期的 `pending` 就結算。
- 倒數：玩家端與主持端都用伺服器時間（`store.js` 的 `serverTime`）算到截止還剩幾秒，跟主持端判斷用的是同一個時鐘；倒數到 0 後顯示「響應時間到了，等主持端結算」。

### 黃昏投票（M6）

- 口徑（企劃 10/13 第 4、7 題、10/15 定案「選邊加總」，加上工程暫定，見 MILESTONES 第 4、7、9 題）：每回合進黃昏時，該桌翻開一張法案。每位入座的人暗中送出「贊成或反對＋影響力出價」（0 到自己目前的影響力），或棄權（出價 0、不選邊）；沒送出算棄權。揭曉前可以改（以最後一次為準），全員送出後的倒數中也可以改；揭曉後不能改。全員送出後倒數 `settings.duskRevealSeconds`（3）秒揭曉，主持端也可以提前揭曉；提醒倒數 `reminderSeconds.dusk`（120）只顯示，不會自動揭曉。
- 結算（`game.js` 的 `resolveDusk`）：贊成與反對各自加總出價，**贊成大於反對才通過**，平手不通過（全員棄權＝0 對 0＝不通過）。選邊的人照出價付影響力，不論輸贏，夾在 0。**先付出價，再套法案效果**：通過套 `onPass`、不通過套 `onFail`；對象 `role`（沒人坐就打空）、`all`；迷霧照白晝的 `advanceFog`，新越過的門檻進 `fogPending`（事件留給 M7）；抽牌、棄牌（資料目前沒有）照白晝的做法。`@指定`（`chosen`）的法案效果這一版不結算，略過，主持端揭曉後顯示一行提示；`todo` 的法案照常投票、記結果，效果全部不結算。選邊與結果一致的人（贊成且通過、反對且沒通過）`aligned`＋1（議會之聲，M9 計分用）；棄權不算。揭曉後公開每個人的選邊與出價、兩邊總和、通過與否（工程暫定）。
- 法案牌堆（工程暫定，`drawBill`）：第一次進黃昏時把 `bills.json` 洗成該桌的一疊（`hostOnly/{code}/{n}/billDeck`），每個黃昏抽最上面一張；抽完時把還沒通過的（不通過的，以及抽過但沒揭曉的）洗回去再抽；一張都不剩（全都通過）就「議會休會」：`dusk` 沒有 `bill`，不投票，主持端可以直接進下一階段。牌庫與棄牌堆因此改成分開寫（`hostOnly/{code}/{n}/deck`、`discard`），日出發牌與白晝結算不會蓋掉同一層的法案牌堆。
- 開黃昏（一筆寫入）：開著主持畫面的主持端（`store.js` 的 `startSettling`）看到已開局的桌進了黃昏、`dusk.round` 不是目前的回合，就抽一張，寫 `version＋1`、`dusk＝{ round, bill, openedAt: 伺服器時間, submitted: 0 }`、剩下的法案牌堆。沒開局（沒人入座）的桌不開黃昏。
- 票：玩家把 `{ table, round, side, bid }` 寫進自己的 `/votes/{code}/{uid}`（`requestVote`，交易＋`serverTimestamp`，同出牌請求），`seq` 一張比一張大，`at` 由伺服器填。每人只有一張，重送蓋掉上一張，所以伺服器上的就是最後一次。規則擋掉格式不對、時間不是伺服器時間、出價超過當下的影響力、棄權帶出價、沒入座、不是黃昏、回合不對、休會、截止之後與揭曉之後的票（見「安全規則」）。
- 已送出人數與倒數：主持端逐人訂閱入座玩家的 `votes/{code}/{uid}`（不在整房的 `votes/{code}` 掛訂閱，理由同響應卡），看到人數變了就整桌交給 `settleDusk`：從伺服器重讀整房的票，算出已送出人數（這一桌、這一回合、截止前的合法票）寫進 `dusk.submitted`（公開，只有數字）；全員送出、還沒有截止時間時，同一筆寫入 `dusk.revealAt＝伺服器現在＋秒數`（主持端估的伺服器時間；秒數是 0 時直接寫伺服器時間；最多 60 秒，`DUSK_MAX_REVEAL_SECONDS`，規則的上限）。提前揭曉（`revealDusk`）寫 `revealAt＝伺服器現在`（`serverTimestamp`）；倒數只剩不到 0.5 秒時不再改。`revealAt` 就是投票的截止時間：規則只收 `now < revealAt` 的票。
- 揭曉（一筆寫入）：主持端用 `.info/serverTimeOffset` 換算伺服器時間，到了 `revealAt＋1 秒`（緩衝，`DUSK_GRACE_MS`）由計時器叫醒，**先記下時間、再從伺服器重讀整房的票**，只算 `table`＝這桌、`round`＝這回合、`openedAt ≤ at ≤ revealAt` 的票（`at ≥ openedAt` 是多一道保險：規則要求每次寫票都帶伺服器時間，合法的票一定在翻開之後；揭曉時不再比對影響力：寫入時規則已經查過，之後影響力少了付的時候夾 0）。寫 `version＋1`、`dusk.result`、`duskLog/{round}`、`bills/{法案編號}`、整份座位（出價、法案效果、`aligned`）、有變的張數與手牌、牌庫與棄牌堆、迷霧的紀錄（`fogMax`、`fogFired`、`fogPending`）與該桌的 `tables/{n}/fog`。規則要求寫結果時伺服器時間已經過了 `revealAt`；主持端估的時間太早被擋下，就等 1 秒重讀重算（最多 3 次）；其他被拒、局面又沒變的情況報錯（同響應窗口），不讓自動化卡住別桌。截止時間已定、還沒揭曉時被推進到同一回合的黑夜，照樣揭曉。翻開之後資料檔才拿掉的法案照樣揭曉（計票、付出價、記結果），沒有效果可算，主持端顯示一行提示。
- 多台主持端：開黃昏、寫人數與截止時間、揭曉都可能同時做，靠 `version` 只成一筆；被拒的一方等局面變了再重讀重算（沿用 M5a）。主持端都不在時，黃昏停在原地；下一台連上就接著做（人數、倒數、揭曉都從伺服器重讀）。
- 畫面：揭曉前，主持端那一桌的「下一階段」停用並寫原因（同響應窗口，畫面擋、規則不擋）；休會與揭曉後可以推進。玩家端與主持端的揭曉倒數、提醒倒數都用伺服器時間算。

### 事件（M7）

- 口徑（企劃 10/15 第 1、2 題，日出一般事件是企劃 10/15 回「照建議」的暫定，加上工程暫定，見 MILESTONES 第 1–3 題）：
  - 迷霧事件：迷霧值「大於」門檻才算越過（剛好 30 不算）；每個門檻每場只在第一次越過時觸發，降回門檻以下再升上來不再觸發；一次越過好幾個門檻由小到大處理；本場最高值記在 `fogMax`。
  - 日出一般事件：每回合日出領薪、抽牌之後，每桌從自己的一般事件牌堆翻 `settings.sunriseEvents` 張（選填設定，預設 1；0＝不翻），第 1 回合也翻。牌堆（`hostOnly/{code}/{n}/eventDeck`）第一次用時把 `kind: deck` 的事件隨機洗成一疊（不照年代排），翻完就把全部一般事件重洗再用；資料檔裡已經沒有的編號略過。
  - 對象：`all`＝該桌入座的人，`role`＝坐那個階層的人（沒人坐就打空），`chosen` 這一版不結算（略過那一項，畫面寫一行提示，同法案）；`todo` 的事件只記紀錄、效果不結算。英鎊、影響力夾 0；抽牌、棄牌照白晝的做法（棄牌由主持端亂數挑）。
- 何時結算（`game.js` 的 `settleFog`、`settleSunriseEvents`、`withFogEvents`）：任何結算讓迷霧新越過門檻時，門檻先照白晝的做法進 `fogPending`；這一筆結算的最後，把 `fogPending` 由小到大逐一處理：找 `kind: fog`、`threshold` 相同的事件（有好幾張時用資料裡的第一張）對這一桌結算，處理中又越過新門檻就接著排、接著處理（每個門檻只觸發一次，一定會停），處理完 `fogPending` 清空；資料裡找不到那個門檻的事件就只記紀錄（`skipped`）。「造成越過的那個效果結算完」的口徑（工程暫定）：一張牌（含它的齒輪加成與響應）、一張法案、一張一般事件整個結算完，才處理迷霧事件；一次日出翻好幾張一般事件時，每張結算完就處理它引發的迷霧事件，再翻下一張。
- 結算＝白晝出牌（`played`）、響應窗口結算（`resolved`）、黃昏揭曉（`revealed`）與日出（含開局）。退回、接下一般牌開窗口、結束這一輪、開黃昏、計人數都不是結算，不處理 `fogPending`。線上舊局面（M5a–M6 只記不處理）留下的 `fogPending`，在下一次結算時一併處理（日出一定會有一次）。
- 寫入：事件的效果、`eventLog` 的新紀錄、清空的 `fogPending`（以及 `fogMax`、`fogFired`、該桌的 `tables/{n}/fog`、有變的手牌與牌庫）都和造成它的那筆結算在同一筆多路徑寫入裡，`version` 一樣只＋1；多台主持端同時做時照舊只成一筆。日出一般事件與日出發牌（開局則與開局）在同一筆；一般事件牌堆照 M6 的教訓用子路徑寫（`hostOnly/{code}/{n}/eventDeck`），不會蓋掉牌庫與法案牌堆。
- 事件紀錄（`games/{n}/eventLog/{i}`，公開）：`{ round, phase, event, kind: 'deck' | 'fog', threshold, skipped }`。`i` 從 0 連號，主持端寫入時接在現有最大的編號後面（`nextEventIndex`）；同一筆結算可以寫好幾筆（例如一般事件＋它引發的迷霧事件）。`phase` 是主持端結算時讀到的那一桌階段（日出事件是 `sunrise`；白晝出牌是 `day`；黃昏法案是 `dusk`，同一回合黑夜才揭曉的是 `night`；響應窗口在推進之後才結算時是那時的階段）。`threshold` 只有迷霧事件才有；`skipped: true`＝這一筆的效果都沒結算（事件是 `todo`，或資料裡沒有這個門檻的事件——這時沒有 `event`）。讀回來可能是陣列也可能是物件（Firebase 的數字鍵），畫面用 `eventLogList` 照編號排好。
- 黑夜（M8）不動迷霧，黑夜的揭曉不處理迷霧事件；線上舊局面留下的 `fogPending` 照舊在下一次結算（最晚下一個日出）處理。
- 畫面：玩家端與主持端從日出到白晝結束都顯示「今日事件」（從 `eventLog` 取這一回合 `phase: sunrise` 的一般事件：名稱、年代、牌面文字、效果與數字），玩家端放在最上面，出牌時也看得到；這一回合觸發的迷霧事件寫「迷霧越過 30：《名稱》」與牌面文字（任何階段）；迷霧值旁邊列已觸發的門檻；另有本場的事件紀錄列表。偷在出牌紀錄寫成「從 ○○ 偷走 3 英鎊」（數量是牌上的數量，4 級連鎖加倍；出牌紀錄沒有記實際拿到多少，對方不夠時以座位上的數字為準）。

### 黑夜（M8）

- 口徑（企劃 10/15 第 8 題雛形，數值都是選填設定；10/15 確認四點；加上工程暫定，見 MILESTONES 第 5、8 題）：每回合進黑夜時，每位入座的人暗中送出一個選擇：**豪賭**（同時選最多賭到第幾層，1–3）、**分贓**或**睡覺**。揭曉前可以改（以最後一次為準），沒送出＝睡覺。全員送出後倒數 `settings.nightRevealSeconds`（3）秒揭曉，主持端也可以提前揭曉；提醒倒數 `reminderSeconds.night`（120）只顯示。
- 結算（`game.js` 的 `resolveNight`，照座位順序；骰子由主持端在揭曉那一次擲，`gamble`）：
  - 豪賭：從第 1 層開始，每層擲一顆六面骰，擲到 `gambleBust[層]` 以下（含）就爆（預設 1、2、3）；過關時累積**變成** `gamblePounds[層]` 英鎊＋`gambleInfluence[層]` 影響力（預設 5／0、20／1、30／1），到選的層數就收手拿走累積。爆了累積歸零，另付 `gambleMedicalFee`（2）英鎊醫藥費，夾在 0（付不起就付到 0）。每過一層再決定繼續或收手的做法是正式版候選，這一版沒做。
  - 分贓：選分贓的人平分 `splitPounds`（6）英鎊（捨去），每人記 `splitSin`（1）點罪孽（座位的 `sin`，M9 計分用）；只有 1 人就拿全部，人多到每人分 0 也照記罪孽。
  - 睡覺：什麼都不發生。黑夜不動迷霧（照雛形），全場公共獎池不做。
- 結果（公開，揭曉後才有）：`night.result`＝`{ players: { uid: { choice, tiers, rolls, bust, pounds, influence, sin } } }`，每位入座的人一筆（沒送出的是 `choice: 'sleep'`）；`tiers`（選的層數）、`rolls`（每一擲的點數，照層排）、`bust`（有沒有爆）只有豪賭有；`pounds`、`influence`、`sin` 是這一夜實際的變化（爆了的醫藥費是負數，付不起時只記實際付的）。`nightLog/{round}` 內容相同，一回合一筆。
- 選擇：玩家把 `{ table, round, choice, tiers }` 寫進自己的 `/nights/{code}/{uid}`（`requestNight`，交易＋`serverTimestamp`，同黃昏的票），`seq` 一筆比一筆大，`at` 由伺服器填；每人只有一筆，重送蓋掉上一筆，伺服器上的就是最後一次。規則擋掉格式不對、時間不是伺服器時間、`tiers` 不是 1–3 或不是豪賭卻帶 `tiers`、沒入座、不是黑夜、回合不對、黑夜還沒開、截止之後與揭曉之後的選擇（見「安全規則」）。
- 開黑夜（一筆寫入）：主持端（`startSettling`）看到已開局的桌進了黑夜、`night.round` 不是目前的回合，就寫 `version＋1`、`night＝{ round, openedAt: 伺服器時間, submitted: 0 }`（蓋掉上一回合的黑夜）。
- 人數、倒數、提前揭曉、揭曉的時間判斷同黃昏：主持端逐人訂閱 `nights/{code}/{uid}`，人數變了就交給 `settleNight` 從伺服器重讀整房的選擇，寫 `night.submitted`；全員送出、還沒有截止時間時同一筆寫 `night.revealAt＝伺服器現在＋秒數`（主持端估的伺服器時間，最多 60 秒；「現在」取寫入前一刻的，不是讀選擇之前的，網路慢時才不會一寫就過了截止）。提前揭曉（`revealNight`）寫 `revealAt＝伺服器現在`。`revealAt` 就是選擇的截止時間：規則只收 `now < revealAt` 的選擇。到了 `revealAt＋1 秒`（`NIGHT_GRACE_MS`）計時器叫醒主持端，**先記下時間、再從伺服器重讀整房的選擇**，只算 `table`＝這桌、`round`＝這回合、`openedAt ≤ at ≤ revealAt` 的，擲骰、結算，一筆寫入：`version＋1`、`night.result`、`nightLog/{round}`、整份座位（英鎊、影響力、罪孽）。
- 多台主持端：開黑夜、寫人數與截止時間、揭曉都靠 `version` 只成一筆，被拒的一方等局面變了再重讀重算（同 `settleDusk`）；另外該桌的回合或階段變了也算「局面變了」：讀到的房間是本機快取，剛被推進到下一個階段時，照舊階段算好的寫入會被規則擋下，這時重讀就會發現已經不用做。揭曉被擋在截止之前（主持端估的時間太早）就等 1 秒重讀重算（最多 3 次）；還是不成功（例如裝置時鐘在連線之後被校正，估的時間快了好幾秒）時，自動化每 5 秒再試一次（`NIGHT_RETRY_MS`），伺服器時間過了截止就揭曉成功。黃昏沒有這個再試（照 M6）；黑夜加上它，是因為畫面擋住揭曉前的「下一階段」，揭曉不成功時那一桌會卡在黑夜。
- 揭曉一定在同一回合的黑夜：揭曉前「下一階段」停用（畫面擋，規則不擋）；被強行推進到下一回合日出時，回合變了，這一夜的選擇不再揭曉，也不結算。
- 手牌上限（企劃 10/13 第 5 題、10/15 確認）：黑夜期間（揭曉前後都可以）手牌超過 `handLimit`（7）的人自己挑要棄哪幾張，寫進 `/discards/{code}/{uid}`＝`{ table, round, cards, seq, at }`（`requestDiscard`，同上）。主持端推進到下一回合日出時（`processSunrise`），從伺服器重讀整房的 `discards` 與各人手牌，在**同一筆日出寫入的最前面**先套用（`game.js` 的 `settleSunrise` → `applyHandLimits`）：挑的合法（這一桌、剛結束的那一回合、張數剛好是超過的張數、都是自己手上的牌，同一張有好幾張時挑幾張要有幾張）就照挑的棄，沒挑或不合法就由主持端亂數棄到上限；棄的牌照座位順序進棄牌堆。接著才領薪、抽牌（牌庫不夠時連剛棄的一起洗回來）、翻一般事件（M7）。手牌、張數、棄牌堆張數與 `hostOnly` 的棄牌堆都在同一筆。
- 畫面：玩家端黑夜卡有三個選項（豪賭附層數與每層爆的機率、獎勵；分贓附「平分 6 英鎊、記 1 罪孽」；睡覺）、「已送出 n／m 人」、提醒倒數、「已送出：豪賭到第 2 層（揭曉前可以改）」、「大家都送出了，n 秒後揭曉」，揭曉後每個人的選擇與結果（豪賭逐層的點數與過關／爆）、自己這一夜的變化與現在的數字；第 1 回合另外顯示黑夜的教學提示（`tutorial.json` 裡階段是黑夜的）。手牌超過上限時另有挑牌（「手牌 9 張，黑夜結束要棄到 7 張：選 2 張」、「已選好」）。主持端每桌有已送出人數、提醒倒數、「提前揭曉」、揭曉後的結果，以及手牌超過上限的人誰挑好了、誰還沒挑（主持端逐人訂閱 `discards/{code}/{uid}`，只比張數，挑的牌在不在手上要到發牌時才查）。

### 終局與計分（M9）

- 什麼時候終局（日落鐘，企劃 10/15 暫定；回合上限是程式的安全值）：主持端在黑夜（揭曉後）按「下一階段」時（`store.js` 的 `advanceOrEnd`），`game.js` 的 `shouldEnd` 照這個順序看：從該桌按「開始」的伺服器時間（`games/{n}/startedAt`）起算過了 `sunsetMinutes`（75）分鐘（剛好 75 分鐘算到了）→ `sunset`；已經是第 `maxRounds`（12）回合 → `maxRounds`；主持端先前按了「這回合結束後算分」（`endAfterRound` 等於目前回合）→ `host`。有一項成立就**不進下一回合日出**，改成終局；都不成立就照舊推進、發牌。各桌各自結束，不等別桌。「現在幾點」用主持端估的伺服器時間（本機時間＋`.info/serverTimeOffset`）。
- 終局那一筆（一筆多路徑寫入）：`tables/{n}/phase＝end`（回合不變）、`games/{n}/version＋1`、`games/{n}/final`。不做日出棄牌、不領薪抽牌、不翻事件，`/discards` 裡挑好的棄牌不用（座位與手牌照終局當下的張數，不真的棄牌；天命判定的手牌另外套上限，見下）。英鎊、影響力、罪孽讀座位的現值（黑夜的變化與分贓的罪孽已經加進座位）；各人的天命從伺服器讀 `/private/{code}/{uid}`（逐人 `get`，不在整房 `/private` 掛訂閱），寫進公開的 `final`，**這時才公開**。黑夜還沒揭曉時不能終局（畫面停用「下一階段」，`advanceOrEnd` 報錯，規則也擋）。兩台主持端同時按，靠 `version` 與規則（已經是 `end` 的桌、`final` 的時間）只成一筆，被拒的一方看到已經終局就停。
- 計分（`game.js` 的 `scoreGame`；企劃 10/15 第 9 題，計分值 10/15 定案），每人：
  - 天命：達成得天命的 `score.points`（v1 都是 10），沒達成 0。判定照天命的 `check`（`destinyDone`，寫法見 [`DATA-FORMAT.md`](DATA-FORMAT.md)「隱藏天命」）：法案看每張法案最後一次的結果 `bills`（沒被表決的算沒通過；通過的法案不會再被抽到），迷霧看終局時的 `tables/{n}/fog` 與本場最高 `fogMax`，英鎊、影響力、手牌看座位（全桌比時同分都算；「多於 rN」比坐那個階層的其他人，沒有別人坐算達成）。手牌先套手牌上限再比（企劃 10/16 定案）：座位的 `handCount` 和 `settings.handLimit` 取較小的（`destinyDone` 多一個參數 `settings`，`scoreGame` 傳卡牌資料的設定），最後一夜也算黑夜結束，最後一回合多抽的牌不算數；多人都到上限時同分都算。發出去的天命在卡牌資料裡找不到時（例如中途重新匯入），天命那一項 0 分、文字寫「（卡牌資料裡找不到天命 dX）」，終局照樣寫得進去。`check` 是 `null`（「判定」空白）的，終局時是待判定（`done` 不存在），主持端在結算表上逐人勾「達成／沒達成」（`judgeDestiny` → `judgeScores`），勾之前算 0 分。
  - 資產：英鎊每 `scoreRates.pounds`（5）點 1 分、影響力每 `scoreRates.influence`（3）點 1 分，各自捨去。
  - 公共成就，各 `achievementPoints`（3）分、同分都給：議會之聲（`parliament`）＝座位的 `aligned` 最多的人（最多是 0 就沒人拿）；齒輪大師（`gear`）＝本場打出過最高級連鎖的人（至少 2 級，被抵銷的那張不算）。齒輪大師從出牌紀錄 `games/{n}/log` 算（全場保留，每筆有 `level`，被抵銷的有 `canceled`），沒有另外存每人的最高級數。
  - 罪孽：座位的 `sin` 每 `sinPerPenalty`（2）點扣 1 分（捨去）。
  - 總分＝天命＋資產＋公共成就－罪孽扣分；名次：總分高的在前，同分比英鎊，再同就並列（例如 1、1、3）。
- `final`＝`{ round, endedAt（伺服器時間）, reason: 'sunset' | 'maxRounds' | 'host', scores: { uid: { destiny: { id, text, done, points }, assets: { pounds, influence, points }, achievements: ['parliament' | 'gear'], sin, sinPenalty, total, rank } } }`：`destiny.points` 是這張天命值幾分（`done` 是 `true` 才算進 `total`），`done` 沒有＝待主持人判定；沒有天命的人 `destiny` 只有 `{ done: false, points: 0 }`；沒拿成就的人沒有 `achievements`；`assets.points`、`sinPenalty` 是換算後的分數。主持端勾天命只改 `scores/{uid}/destiny/done` 與有變的 `total`、`rank`，每次 `version＋1`。兩場制（M9 下一段）要在這之上加「第幾場」與兩場合計。
- 最後一回合的黑夜：手牌超過上限的人不再被要求挑棄牌（玩家畫面寫「不用棄牌，算分時超過上限的照上限 7 張算」，主持端寫「手牌超過上限的人不用棄牌，算分時超過上限的照上限 7 張算」、不列「還沒挑」；7 是 `handLimit`），因為終局不做日出的棄牌，天命判定的手牌照上限算。
- 「這回合結束後算分」（試玩時間不夠時用）：主持端每桌一個鈕，按下寫 `endAfterRound＝目前回合`（`setEndAfterRound`，`version＋1`），取消＝刪掉；這一回合黑夜揭曉後按「下一階段」就算分。日落鐘到了或到了回合上限時不再顯示這個鈕。
- 自動化（`startSettling`）遇到 `end` 的桌什麼都不做：不開黑夜、不揭曉黃昏、不處理請求、不重試、不報錯（`settleRequest`、`settleWindow`、`settleDusk`、`settleNight` 也各自擋）。
- 畫面：主持端每桌有日落鐘（開局後幾分幾秒、還剩幾分幾秒；到了寫「時間到了——這回合結束後算分」）、「這回合結束後算分」與取消；該算分的那一回合黑夜，「下一階段」寫成「下一階段（算分）」。終局後該桌顯示結算表：照名次排，每人的天命（內容、達成條件、是否達成）、資產換算、公共成就、罪孽扣分與總分的算式，「判定」空白的天命有「達成／沒達成」可勾；「下一階段」不再出現。玩家端在最後一回合（`shouldEnd` 成立，日落鐘照伺服器時間算）顯示「這是最後一回合」；終局後最上面是結算：自己的分數明細（每一項怎麼算的）、全桌名次、每個人的天命與是否達成。

## 公開與私密分兩棵樹

資料庫的規則向下繼承：上層給了讀取權，下層收不回。`/rooms/{code}` 整棵是「知道房號就能讀」，所以**不能公開的東西不可以放在它底下**。

- 公開（`/rooms/{code}/games/{n}`）：座位順序、階層、英鎊、影響力、手牌**張數**、罪孽、議會之聲次數、牌庫與棄牌堆**張數**、白晝輪次、出牌紀錄（打出的牌本來就公開，這是公開樹裡唯一出現牌編號的地方）、黃昏翻開的法案與已送出**人數**、揭曉後的票與結果、翻過與觸發過的事件（`eventLog`；還沒翻的一般事件在 `hostOnly`）。同桌都看得到。
- 私密（`/private/{code}/{uid}`）：手牌內容、隱藏天命、請求被退回的原因（`notice`）。本人與主持端可讀，只有主持端可寫；玩家用 `watchPrivate` 訂閱自己那一筆。終局時主持端把每個人的天命（編號與文字）與是否達成抄到公開的 `final`（M9）。
- 只有主持端（`/hostOnly/{code}/{n}`）：牌庫順序（陣列順序＝抽牌順序）、棄牌堆、還沒抽的法案、還沒翻的一般事件。
- 請求（`/requests/{code}/{uid}`）：玩家要出哪張牌、指定誰。本人可寫可讀，該房主持端可讀整個 `/requests/{code}`；別的玩家讀不到（出牌前不洩漏手上有什麼）。
- 票（`/votes/{code}/{uid}`）：玩家自己的選邊與出價。本人可寫可讀，該房主持端可讀整個 `/votes/{code}`；別的玩家讀不到，揭曉後由主持端抄到公開樹（`dusk.result`、`duskLog`），`/votes` 本身一直不公開。
- 黑夜的選擇（`/nights/{code}/{uid}`）與挑的棄牌（`/discards/{code}/{uid}`）：同票，本人可寫可讀，該房主持端可讀整房；別的玩家讀不到。揭曉後主持端把選擇與結果抄到公開樹（`night.result`、`nightLog`）；挑的棄牌一直不公開（棄掉的牌進只有主持端讀得到的棄牌堆）。
- 陣列在資料庫裡是數字鍵的物件（`0`、`1`…），規則照這樣檢查；空陣列寫進去等於沒有這個欄位，讀回時當空的。

## 誰負責計算

主持端裝置。洗牌、發牌、揭曉、計分都由它算完後一次寫入；玩家的裝置只送出自己的選擇、訂閱結果。

## 卡牌資料從哪來、怎麼進遊戲

- 卡牌與數值是 `play/data/` 的七個 JSON 檔（設定、階層、行動牌、法案、事件、隱藏天命、教學提示 `tutorial.json`），跟網頁一起部署成靜態檔，不放資料庫。
- 瀏覽器由 `js/gamedata.js` 用 `fetch` 讀同源的 `./data/*.json`，用 `js/data.js` 的檢查；讀不到或有錯誤時畫面頂端顯示「卡牌資料有問題，請找工作人員」，開局與發牌停用。主持端用它洗牌、發牌、結算；玩家端用同一份檔把牌編號顯示成牌名與牌面文字。Node 測試注入讀檔函式，讀同一份檔。
- 正本是企劃填的試算表，一列一張，樣板在 `docs/data-templates/`。匯出的 CSV 用 `npm run data:import -- <資料夾>` 轉成 JSON，寫完自動檢查；`npm run data:check` 與 `npm test` 也會檢查。資料檔不手改，下次匯入會整個蓋掉。
- 牌的效果是結構化的物件（`{ op, target, amount }`），試算表用文字語法填（例如 `英鎊+5@自己；迷霧+3`），匯入時轉換；轉不了的標 `todo`、保留原文，先不結算。欄位與語法見 [`DATA-FORMAT.md`](DATA-FORMAT.md)。
- 格式定義與檢查在 `js/data.js`，是純函式，瀏覽器與 Node 共用；CSV 解析與轉換只在匯入時用，放在 `scripts/lib/`。
- 資料檔是公開的靜態檔，任何人都讀得到全部的牌與天命內容；要保密的是「誰拿到哪一張」，那放私密樹。
- 迷霧門檻：白晝結算讀 `settings.json` 的 `fogThresholds`；`js/rules.js` 的 30／60／90 只剩 `applyFog` 與 `advanceFog` 的預設值在用。

## 安全規則（`database.rules.json`）

- 預設全部不可讀寫；`/rooms` 不可列舉，房號就是門票。
- `/rooms/{code}`：已登入者可讀。
- `meta`：只能在不存在時建立，`hostUid` 必須是自己。
- `tables`：只有主持端可寫，並檢查階段、回合、迷霧值的範圍。M9：階段可以是 `end`；進 `end` 只能從黑夜、回合不變，而且同一筆寫入要新寫 `games/{n}/final`；已經是 `end` 的桌，階段與回合都不能再改（條件都在 `tables/{n}` 那一層，只改一個欄位的更新也檢查）；桌子刪不掉（`tables` 那一層要求原本有的桌號寫入後還在、房間那一層擋整個 `tables` 拿掉），免得刪掉再重建繞過終局。
- `players/{uid}`：只能寫自己那一筆，房間必須存在，暱稱 1–12 字、桌號在範圍內。
- `hosts/{uid}`：只有現任主持端可寫，值只能是 `true` 或刪除；沒有人能把自己加進名單。
- `hostRequests/{uid}`：本人可寫（房間必須存在），本人或主持端可刪；內容只有 `requestedAt`。
- `presence/{uid}`：只能寫自己那一筆，值只能是 `true` 或刪除，房間必須存在。
- `games/{n}`：只有主持端可寫、不能刪；該桌必須存在，而且同一筆寫入裡 `deals/{n}` 也要在。每筆寫入的 `version` 都要剛好是舊值＋1（還沒有 `version` 時只能寫 1），不管改的是哪個欄位；沒帶、沒＋1 或跳號都整筆被拒。欄位逐一檢查（`startedAt` 只能寫一次；座位 `order` 0–5、`role` 是編號格式、英鎊與影響力與手牌張數與罪孽是 0 以上的整數；牌庫與棄牌堆張數同；`startOrder` 0–5，`turn` 或 `pending` 存在後就不能改；`turn` 的 `round` 1 以上、`index` 0–6、`plays` 與 `level` 0 以上、`gear` 1–32 字；`fogMax` 與 `fogFired`、`fogPending` 的每一項是 0–100 的整數；`lastSeq/{uid}` 只能給入座的人、不往回、不超過他自己請求的 `seq`；`pending` 的 `id` 是 1–40 字的英數 `-_`、`by`／`target`／`chainTarget` 是入座的人、`seq` 與 `level` 1 以上、`card` 是編號格式、`openedAt` 必須是伺服器時間、`seconds` 0–60，存在時不能換成另一張（要先結算刪掉）；出牌紀錄的 `by`、`target`、`chainTarget` 要是入座的人，`card` 是編號格式，`level` 1 以上，`response` 只有 `by`（入座的另一位）與 `card`，`canceled` 只能是 `true` 而且要有 `response`），多的欄位一律拒絕。
- `deals/{n}`：只有主持端可寫、不能刪；整數、比舊值大、等於 `tables/{n}/round` 目前的值，而且該桌已開局（`games/{n}` 在）。
- `/private/{code}/{uid}`：本人可讀，該房主持端可讀整個 `/private/{code}`；只有主持端可寫。內容只有 `table`（必填，桌號在範圍內）、`hand`（牌編號的陣列）、`destiny`（天命編號）、`notice`（`seq` 1 以上的整數、`reason` 是小寫英文與 `-` 的原因代碼）；編號照 `js/data.js` 的 `ID_PATTERN`。
- `/hostOnly/{code}`：只有該房主持端可讀寫。每桌只有 `deck`、`discard`、`billDeck`、`eventDeck`（M7）四個編號的陣列。
- `/requests/{code}/{uid}`：只有本人可寫（房間必須存在、不能刪），`seq` 要比舊的大；本人可讀，該房主持端可讀整個 `/requests/{code}`。內容只有 `seq`、`type`（`play`、`pass` 或 `respond`）、`at`（必填，必須剛好是伺服器時間；M6 起在整筆那一層檢查，只改其他欄位、留著舊時間的更新也會被拒）、`card`（`play`、`respond` 必填，編號格式）、`target`、`chainTarget`（uid 格式）、`pending`（`respond` 必填、也只有 `respond` 能帶，1–40 字的英數 `-_`），多的欄位拒絕。誰能出什麼牌、響應得對不對由主持端結算時檢查，規則只管格式、寫入者與時間。
- `/votes/{code}/{uid}`（M6）：只有本人可寫（房間必須存在、不能刪），本人可讀，該房主持端可讀整個 `/votes/{code}`。必有 `table`、`round`、`side`、`bid`、`seq`、`at`，多的欄位拒絕；下面的條件都寫在整筆那一層，每次寫入（包括只改幾個欄位的更新）都整筆重新檢查——Realtime Database 只檢查這次寫到的欄位，寫在欄位上的條件會被「只改別的欄位」的更新繞過：`seq` 比舊的大；`at` 剛好是伺服器時間；`table` 是 `1`–`6` 的字串，自己在那一桌有座位、那一桌在黃昏、已翻開法案（不是休會）、還沒有結果、沒有截止時間或伺服器時間還沒到截止時間；`round` 等於那一桌目前的回合、也等於 `dusk.round`；`side` 是 `yes`、`no`、`abstain`；`bid` 是 0 以上的整數、不超過自己座位上當下的影響力，棄權只能是 0。
- `games/{n}` 的黃昏欄位（M6，寫入者照 `games`，只有主持端）：`dusk` 必有 `round`、`openedAt`、`submitted`，`round` 等於該桌目前的回合；換到新的回合（開黃昏）時那一桌要在黃昏，同一回合裡 `openedAt`、`bill` 不能改，`revealAt`、`result` 有了就不能拿掉；`bill` 是編號格式（沒有＝休會）；`openedAt` 寫入時是伺服器時間；`submitted` 0–6 的整數；`revealAt` 是整數，寫入時在伺服器時間到之後 60 秒之間，之後只能提早、不能延後；`result` 只能寫一次，要有法案、有截止時間而且伺服器時間已經過了截止時間，`yes`、`no` 是 0 以上的整數、`passed` 是布林而且等於「`yes` 大於 `no`」，`votes` 的鍵是入座的人、內容只有 `side` 與 `bid`（格式同票）。`duskLog/{round}` 只能寫一次、鍵等於目前的回合，跟 `dusk.result` 一起寫、法案相同，欄位同 `result` 再加 `bill`。`bills/{法案編號}` 只能是 `passed` 或 `failed`，要跟這一回合的 `dusk.result` 一起寫、法案相同、結果一致。座位的 `aligned` 是 0 以上的整數。`dusk`、`duskLog`、`bills` 整個拿掉會被拒。多的欄位一律拒絕。
- `games/{n}/eventLog/{i}`（M7，寫入者照 `games`，只有主持端）：條件寫在整筆那一層（`$i`），每次寫入（包括只改一個欄位的更新）都整筆檢查——只能寫一次（已有的紀錄任何寫入都被拒）、必有 `round`、`phase`、`kind`，`round` 等於該桌目前的回合；`kind` 是 `deck` 時要有 `event`、不能有 `threshold`；`kind` 是 `fog` 時要有 `threshold`，而且要有 `event` 或 `skipped: true`。欄位上只留格式：`round` 1 以上的整數、`phase` 是四個階段之一、`event` 是編號格式、`kind` 是 `deck|fog`、`threshold` 0–100 的整數、`skipped` 是布林，多的欄位拒絕；鍵是數字。刪除：Realtime Database 刪掉一個節點時不跑那個節點的 `.validate`，所以在 `eventLog` 那一層要求有子節點（不能寫成一個值），並逐號比對編號 0–63 的紀錄「原本有的，寫入後還要在」，`games/{n}` 那一層另外擋「整份 `eventLog` 拿掉」。編號 64 以後的紀錄規則擋不了刪除（一場用不到這麼多：每回合一張一般事件＋最多 3 個迷霧事件）。
- `/nights/{code}/{uid}`（M8）：只有本人可寫（房間必須存在、不能刪），本人可讀，該房主持端可讀整個 `/nights/{code}`。必有 `table`、`round`、`choice`、`seq`、`at`，多的欄位拒絕；條件都寫在整筆那一層（同票）：`seq` 比舊的大；`at` 剛好是伺服器時間；`table` 是 `1`–`6` 的字串，自己在那一桌有座位、那一桌在黑夜；`round` 等於那一桌目前的回合、也等於 `night.round`（黑夜已開）；`night` 還沒有結果、沒有截止時間或伺服器時間還沒到截止時間；`choice` 是 `gamble`、`split`、`sleep`，`tiers` 只有 `gamble` 有、而且是 1–3 的整數。
- `/discards/{code}/{uid}`（M8）：寫入者與讀取權同上。必有 `table`、`round`、`cards`、`seq`、`at`，多的欄位拒絕；整筆那一層檢查 `seq` 比舊的大、`at` 剛好是伺服器時間、`table` 是 `1`–`6` 的字串而且自己在那一桌有座位、那一桌在黑夜（揭曉前後都可以）、`round` 等於那一桌目前的回合、`cards` 不是空的。`cards` 是牌編號的陣列，最多 30 張（編號 0–29；規則讀不到資料檔裡的手牌上限，實際張數與牌在不在手上由主持端發牌時查）。
- `games/{n}` 的黑夜欄位（M8，寫入者照 `games`，只有主持端）：照黃昏的寫法。`night` 必有 `round`、`openedAt`、`submitted`，`round` 等於該桌目前的回合；換到新的回合（開黑夜）時那一桌要在黑夜，而且一定是剛開的（`openedAt` 是伺服器時間、`submitted` 是 0、沒有 `revealAt` 與 `result`，不能沿用上一回合的時間）；同一回合裡 `openedAt` 不能改，`revealAt`、`result` 有了就不能拿掉；`openedAt` 寫入時是伺服器時間；`submitted` 0–6 的整數；`revealAt` 是整數，寫入時在伺服器時間到之後 60 秒之間，之後只能提早；`result` 只能寫一次，要有截止時間而且伺服器時間已經過了截止時間，要跟這一回合的 `nightLog/{round}` 一起寫，只有 `players`。`nightLog/{round}` 只能寫一次、鍵等於目前的回合、`night.round` 也是這一回合，而且 `night.result` 要在同一筆寫入裡新寫（一起寫）。`players` 的鍵是入座的人，內容：`choice` 是三者之一；豪賭必有 `tiers`（1–3）、`rolls`（每一擲 1–6 的整數，最多 `tiers` 個，沒爆時剛好 `tiers` 個）與 `bust`（布林），其他選擇不能有這三個欄位；`pounds` 是整數（醫藥費是負數）；`influence`、`sin` 是 0 以上的整數；多的欄位拒絕。`night`、`nightLog` 整個拿掉會被拒。
- `games/{n}` 的終局欄位（M9，寫入者照 `games`，只有主持端）：`endAfterRound` 是整數、等於該桌目前的回合，或刪掉。`final` 的條件都寫在整筆那一層（`final`），每次寫入（包括只改一個欄位的更新）都整筆檢查：必有 `round`、`endedAt`、`reason`、`scores`；該桌的 `phase` 是 `end`（同一筆寫入一起改的也算）；`round` 等於該桌目前的回合；`endedAt` 第一次寫時是伺服器時間，之後不能改（連「再寫一次伺服器時間」也不行）；`reason` 是 `sunset`、`maxRounds`、`host` 之一。第一次寫時，該桌原本在黑夜、`night.round` 是這一回合而且黑夜已經揭曉（有 `night.result`）；之後 `round`、`reason` 不能改。`scores` 的鍵是入座的人，必有 `destiny`、`assets`、`sin`、`sinPenalty`、`total`、`rank`；第一次寫之後不能多出新的人，天命的編號、文字、分數，資產的三個數，成就，罪孽與扣分都不能改（只剩 `destiny.done`、`total`、`rank` 能改）。欄位格式：`destiny` 必有 `points`，`id`（編號格式）與 `text`（1–500 字）要嘛都有、要嘛都沒有，`done` 是布林；`assets` 的三個數、`points`、`sin`、`sinPenalty` 是 0 以上的整數；`total` 是整數；`rank` 是 1 以上的整數；`achievements` 是 `parliament`、`gear` 的清單（最多兩項）；多的欄位一律拒絕。`final` 有了就不能整個拿掉。
- 主持端的判斷各處都一樣：`meta/hostUid` 是自己，或 `hosts/{uid}` 是 `true`。

## 身分

匿名登入，不收任何個人資料（玩家只輸入暱稱與桌號）。身分存在瀏覽器裡，關掉分頁再開還是同一個人；清除瀏覽器資料或換瀏覽器就是新的人。主持端離開主持畫面後，同一個身分用房號就能回來。網址加 `?slot=名稱` 可以讓同一個瀏覽器的不同分頁當不同的人，開發與測試用。

## 已知限制

- 同時連線上限 100，每支手機、每個分頁、投影電腦各算 1。
- 沒有雲端函式：所有主持端都離線時，各桌就停在原地；規則只能檢查格式，算得對不對要信任主持端。
- 備援主持機必須在開場前由現任主持端核准。主持機掛掉之後才來申請的，沒有人能核准；主持端清除瀏覽器資料後就是新的身分，同樣要重新申請。
- 主持名單沒有移除的畫面（規則允許主持端刪除），核准前務必核對確認碼。確認碼只防認錯人，不是密碼。
- 上線狀態每個身分只有一筆：同一個身分開兩個分頁時算同一個人；斷線要等伺服器察覺連線中斷才會標示，網路突然消失（不是正常關閉）時會比較慢，實際多久要用實機量。
- import map 需要 iOS Safari 16.4 以上／Chrome 89 以上；更舊的瀏覽器會看到「請更新」的說明。
- 暱稱長度以 UTF-16 計，表情符號多半一個算 2。
- 房間不會自動刪除，活動後要另外清；`/private`、`/hostOnly` 兩棵樹也要一起清。
- 規則要求英鎊、影響力不小於 0：白晝、黃昏與事件（M7）的結算已經夾在 0 以上（偷只拿走對方有的）；之後的結算（黑夜）也要夾，否則整筆寫入會被拒。
- `database.rules.json` 加了 `version` 守門與新的樹，正式專案的規則要跟新版網頁一起換：只推網頁不發布規則，新版寫不進去（舊規則拒絕 `version`、`turn` 等新欄位與 `/requests`）；只發布規則不推網頁，舊版網頁的開局與發牌會被拒（沒帶 `version`）。兩個一起做完，開一間新房走一次開局到白晝出牌。舊局面（沒有 `version`）第一次被新版寫入時從 1 開始。響應卡（M5b）又加了 `pending`、出牌紀錄的新欄位、`respond` 請求，並把請求的 `at` 收緊成剛好等於伺服器時間：只推網頁不發布規則，新版開不了響應窗口（`pending` 被拒）；只發布規則不推網頁，M5a 的網頁照樣能出牌（它的請求本來就用伺服器時間）。發布後開新房走一次出牌、響應、抵銷、時間到。
- 規則不檢查結算時的階段，也不檢查結算算得對不對（例如成本有沒有付、效果有沒有照牌面）：沒有雲端函式，只能信任主持端。
- 主持端在每個請求上會多讀幾次資料庫（各入座玩家的手牌、牌庫）；六桌同時出牌時的流量要在容量演練（M12）實測。響應窗口每結算一次還要重讀整房的請求（一房最多約 36 筆小資料），一樣在 M12 量。
- 響應的時間判斷靠各主持端估的伺服器時間（`.info/serverTimeOffset`，連線時量的）：估得比實際早超過 1 秒緩衝時，主持端可能在截止前就當作沒人響應，之後才送到的合法響應會被退回（局面不會壞，只是那位玩家白按）；估得晚只會讓結算晚一點。網路慢的玩家，響應要在截止前送到伺服器才算（以伺服器收到的時間為準），畫面上的倒數也用伺服器時間，但按下去到送達之間的延遲沒有補償。
- 主持端都斷線時，等著響應的牌停在那裡，玩家畫面倒數到 0 後顯示「響應時間到了，等主持端結算」；主持端連回來才結算，讀的是伺服器上的請求。窗口中「下一階段」只有畫面擋，規則不擋。
- 黃昏投票（M6）又加了 `/votes`、`games/{n}` 的 `dusk`、`duskLog`、`bills`、座位的 `aligned` 與 `hostOnly` 的 `billDeck`：只推網頁不發布規則，新版開不了黃昏（`dusk` 被拒，主持端畫面頂端報錯，「下一階段」停在「法案還沒翻開」）、玩家也送不出票；只發布規則不推網頁，M5b 的網頁照樣能玩到黃昏（它不寫這些欄位），但它的日出發牌與白晝結算是整個 `hostOnly/{code}/{n}` 一起寫，會把新版留下的法案牌堆蓋掉（新舊網頁混用同一間房時才會發生，下一次黃昏從沒通過的法案重洗）。發布後開新房走一次黃昏：全員送出、倒數揭曉、提前揭曉、進黑夜。
- 事件（M7）又加了 `games/{n}/eventLog` 與 `hostOnly` 的 `eventDeck`：只推網頁不發布規則，新版的開局、日出發牌、以及讓迷霧越過門檻的結算都會被拒（`eventLog`、`eventDeck` 是舊規則不認得的欄位），主持端畫面頂端報錯；只發布規則不推網頁，M6 的網頁照樣能玩（它不寫這些欄位、不處理迷霧事件，`fogPending` 只記不處理），同一間房混用新舊網頁時，舊網頁的日出不翻一般事件。發布後開新房走一次：開局看到第 1 回合的一般事件、第 2 回合日出再翻一張、白晝讓迷霧越過 30 看到迷霧事件。線上舊局面留下的 `fogPending` 會在新版的下一次結算（最晚下一個日出）處理掉。
- 黃昏的截止時間（`revealAt`）在全員送出時由主持端用估計的伺服器時間寫成「現在＋3 秒」：規則收的是「伺服器時間到之後 60 秒之間」，估得比實際晚超過 3 秒時會被拒，主持端等 3 秒沒看到局面變化就在畫面頂端報錯「黃昏沒有結算成功」；這時按「提前揭曉」（寫的是伺服器時間）就能接著走。揭曉讀票的時間用的也是估計的伺服器時間加 1 秒緩衝：估得比實際早超過 1 秒時，規則（要求揭曉時已過截止）會擋下太早的揭曉、主持端等一下再試；在截止前最後一刻才改的票，若主持端讀票時剛好還沒到截止、寫入時已過截止，可能沒算到（要估錯 1 秒以上才會發生）。網路慢的玩家，票要在截止前送到伺服器才算（以伺服器收到的時間為準，按下去到送達之間的延遲沒有補償）。
- 黃昏揭曉時出價照當時送出的數字計票，付的時候夾在 0：投票後影響力才變少（例如黃昏時才結算的響應卡）的人，付的比出價少，畫面上的「你付了」仍寫出價。
- 主持端都斷線時，黃昏停在原地（人數不更新、倒數到 0 後玩家畫面寫「投票截止了，揭曉中…」）；主持端連回來才揭曉，讀的是伺服器上的票。黃昏中「下一階段」只有畫面擋，規則不擋：投票中被強行推進到黑夜，這張法案就不會揭曉（票也送不進來了），下一回合照常抽下一張；這張沒揭曉的法案下次重洗時會回到牌堆。
- 黑夜（M8）又加了 `/nights`、`/discards`、`games/{n}` 的 `night` 與 `nightLog`：只推網頁不發布規則，新版開不了黑夜（`night` 是舊規則不認得的欄位，主持端畫面頂端報錯「黑夜沒有結算成功」，「下一階段」停在「黑夜還沒開始」），玩家也送不出選擇與挑的棄牌，而且日出發牌讀 `discards` 會被拒（舊規則沒有這棵樹的讀取權），**連第 2 回合起的日出都發不出去**；只發布規則不推網頁，M7 的網頁照樣能玩（它不寫這些欄位、黑夜什麼都不做、日出不管手牌上限）。新舊網頁混用同一間房時，舊網頁發的日出不套手牌上限，而且舊網頁的主持畫面會讓沒揭曉的黑夜直接推進。發布後開新房走一次：第 1 回合黑夜全員送出倒數揭曉、第 2 回合有人沒送時提前揭曉、手牌 8 張時挑 1 張棄，第 3 回合日出看手牌。
- 黑夜的時間判斷與黃昏相同（估計的伺服器時間、1 秒緩衝、截止前送到伺服器才算），網路慢時的行為也相同，見上一條。黑夜揭曉前被強行推進到下一回合，這一夜不結算。
- `nightLog` 只擋「整份拿掉」，主持端單獨刪掉其中一回合的紀錄規則擋不了（同 `duskLog`；刪了也寫不回去，因為紀錄只能跟這一回合的結果一起寫）。主持端本來就是被信任的一方（結算得對不對也只能信任它）。
- 手牌上限挑的棄牌最多 30 張（規則的上限）；超過 37 張手牌的人要棄 31 張以上時挑不了，日出照亂數棄。主持端畫面列「還沒挑」只比張數，挑的牌不在手上（例如被黃昏法案棄掉了）時畫面仍寫已挑好，日出時照亂數棄。
- 資料檢查目前要求 `responseSeconds` 1 以上；程式把 0 當作不開窗口（測試用），要讓試算表填 0 時，`js/data.js` 的檢查與匯入的測試要一起改。
- 局面不能從畫面刪掉重開；要重來就開新房。第二場（兩場制，M9 下一段）的重置要另外設計（例如局面多一層「第幾場」、`final` 照場次存）。
- 終局（M9）又加了 `tables/{n}/phase` 的 `end`、`games/{n}` 的 `final` 與 `endAfterRound`：只推網頁不發布規則，新版算不了分（舊規則不認得 `end` 與 `final`，主持端等 3 秒後畫面頂端報錯「算分沒有成功」；該算分的那一桌「下一階段」一直是算分，就停在黑夜），「這回合結束後算分」也按不了（`endAfterRound` 是舊規則不認得的欄位）；只發布規則不推網頁，M8 的網頁照樣能玩（它不寫這些欄位），只是沒有終局，一直玩下去。新舊網頁混用同一間房時，舊網頁的主持畫面看到 `end` 的桌會顯示不出階段，按「下一階段」時交易會丟錯（舊版的推進不認得 `end`；規則也不讓它改），不會動到結算。發布後開新房走一次：主持端按「這回合結束後算分」、黑夜揭曉後按「下一階段（算分）」、看結算表與玩家畫面、勾一張「判定」空白的天命。
- 日落鐘的「現在」是按「下一階段」那台主持端估的伺服器時間（本機時間＋`.info/serverTimeOffset`），`startedAt` 是伺服器時間；主持端的時間估錯幾秒，終局就早或晚幾秒（只影響剛好卡在 75 分鐘的那一回合）。規則不檢查「日落鐘到了沒」（規則讀不到資料檔的分鐘數），也不檢查分數算得對不對、名次排得對不對、天命判定對不對：同其他結算，只能信任主持端。
- `final` 裡單獨一個人的分數，主持端刪得掉（規則只擋「整份拿掉」與「之後多出新的人」；同 `nightLog` 的單筆）。
- 終局不真的棄牌（座位的手牌張數是終局當下的），天命判定裡的手牌先套手牌上限再比（企劃 10/16 定案），「手牌最多」這類判定不會因為最後一回合多抽而佔便宜；上限照主持端讀到的卡牌資料，終局後才改上限不會重算。最後一夜的畫面不叫人挑棄牌，是照那台裝置估的時間判斷「這一回合結束就算分」：日落鐘剛好在黑夜裡到的那幾秒，畫面與主持端按下去那一刻的判斷可能差一點；若最後沒有算分、進了下一回合日出，沒挑的人照舊被隨機棄。
- 開局後換桌或離開房間的人，座位照舊留著；離開的人在畫面上顯示「已離開房間」，日出照樣領薪抽牌。
