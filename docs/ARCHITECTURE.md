# 架構決定：多人連線版

適用範圍：`play/`（「一日英國人：女皇陛下萬歲！」的遊戲網頁）。狀態：已採用，目前做到白晝出牌（M5a：輪流出牌、成本與效果、齒輪連鎖；響應卡是 M5b）。

## 一句話

靜態網頁（原生 HTML＋CSS＋ES modules，不用框架、不用打包工具）＋ Firebase Realtime Database 當唯一的狀態來源＋匿名登入。我方沒有自己的伺服器：階段推進與計算由主持端裝置做完後寫入資料庫，其他人只訂閱。

## 條件

- 活動當天 6 桌 × 6 人＋工作人員，約 51 台裝置，單場 90 分鐘。
- 用免費方案（Firebase Spark）：同時連線上限 100、不綁卡、資料庫放新加坡。免費方案沒有雲端函式。
- 網頁程式、字型、圖片全部自行託管，不引用第三方內容傳遞網路。

## 選了什麼、為什麼

- **原生網頁，不打包。** 頁面小（目前載入的檔案壓縮後約 127 KB），部署就是複製檔案，手機上出問題可以直接看原始碼。
- **唯一的例外是官方 Firebase JS SDK**（固定版本、自行託管）。斷線重連、離線期間的寫入排隊、登入憑證自動更新，正好是現場最容易出事的地方，不自己重寫。
- **本機用模擬器開發與測試。** `demo-` 開頭的專案代號完全離線、不需要帳號。正式專案只是換一組設定（見下方「環境」），測試直接跑同一份 `js/store.js`，不寫第二套假後端。

## 環境

- `js/config.js` 有兩組設定：本機模擬器（`demo-one-day-briton`）與正式專案（免費方案、資料庫在新加坡，只開匿名登入與 Realtime Database）。網址帶 `?env=emu`／`?env=prod` 就照參數；沒帶的話，本機（`localhost`、`127.0.0.1`、`::1`）用模擬器，其他主機用正式專案。選擇規則是純函式，有單元測試。
- 靜態檔放 GitHub Pages 的 `/one-day-briton/play/`，不用 Firebase Hosting。
- 正式專案的設定值（`apiKey` 等）是公開的識別碼，跟網頁一起公開；擋人的是安全規則。
- 安全規則目前在 Firebase 主控台手動發布，內容以 repo 的 `database.rules.json` 為唯一來源：先改這個檔、跑過 `npm run test:sync`，再整份貼到主控台發布；不在主控台上直接改。

## 放棄了什麼

- **自己寫即時伺服器**：免費主機會休眠或重啟，場中一斷全場停。
- **Cloudflare Workers＋Durable Objects**：伺服器與重連協定都要自己寫。
- **Firestore**：以讀取次數計費，每台裝置每收到一次變動都算讀取，一場活動的監聽量會超過每日免費額度。

## 資料模型

房＝一個場次；桌＝房內第 1–6 桌，各自有回合與階段。

```
/rooms/{code}                     code＝6 碼大寫英數，去掉 0 O 1 I L
  /meta               { hostUid, createdAt, tableCount }  建立後不可改；hostUid＝開房的人
  /tables/{n}         { round, phase, fog, updatedAt }    n＝1–6；round 從 1 起；fog 0–100
  /players/{uid}      { name, table, joinedAt }           uid＝匿名登入的身分
  /hosts/{uid}        true                                被核准的其他主持端（不含開房的人）
  /hostRequests/{uid} { requestedAt }                     想當主持端的裝置自己寫入，等核准
  /presence/{uid}     true                                連著的時候才有；斷線由伺服器代為移除
  /games/{n}          { startedAt, seats, deckCount, discardCount, version, … }  該桌的局面，開局時建立
    /seats/{uid}      { order, role, pounds, influence, handCount, sin }  order＝座位 0–5（順時針）；sin 沒有＝0
    /version          整數                                每筆改到這一桌局面的寫入都要「新＝舊＋1」，開局寫 1
    /startOrder       0–5                                 第 1 回合的起始座位，沒設＝0
    /turn             { round, index, plays, gear, level } 白晝輪到第幾位、他這一輪出了幾張、上一張的齒輪與級數
    /fogMax、/fogFired、/fogPending                         本場迷霧最高值、已觸發的門檻、新越過還沒處理的門檻
    /lastSeq/{uid}    整數                                已處理過的請求序號
    /log/{id}         { round, by, card, level, target, at }  出牌紀錄（打出的牌本來就公開）
  /deals/{n}          整數                                已處理過日出的回合數
/private/{code}/{uid} { table, hand: [牌編號…], destiny, notice }  本人與主持端可讀，見下一節
/hostOnly/{code}/{n}  { deck: [牌編號…], discard: [牌編號…] }  只有主持端可讀寫
/requests/{code}/{uid} { seq, type, card, target, chainTarget, at }  玩家自己寫，本人與主持端可讀
```

- 階段：`sunrise` 日出 → `day` 白晝 → `dusk` 黃昏 → `night` 黑夜 → 下一回合的日出。
- 推進一律用交易（transaction），而且帶著「我以為現在是第幾回合、哪個階段」；資料庫現況不一樣就不動。連點兩下或兩台主持端同時按，都只會前進一步。
- 主持端＝開房的人，加上主持名單（`hosts`）上的人。備援裝置在首頁用房號「以主持端進入」留下申請，現任主持端核對兩邊畫面上相同的 4 碼確認碼（由申請者的 uid 算出）後核准；核准是一次寫入（加進名單＋清掉申請）。名單上的人也能核准別人，所以「全場一台主持機＋備援機」與「每桌帶玩員各自操作」都適用。
- 上線狀態不定時回報、不寫時間戳：每次連上都先請伺服器登記「斷線時移除」再寫入 `presence`，離開房間時自己移除。自己的連線狀態另外看 `.info/connected`，斷線時畫面頂端提示，不會把人送回首頁。
- 迷霧值 0–100，超過 30／60／90 觸發事件。骨架只有純函式（夾在範圍內、回報跨過哪些門檻）與顯示。
- 開局（主持端每桌一個「開始」鈕）：`players` 裡 `table＝n` 的人入座，0 人或超過 6 人不能開，少於 3 人可以開但畫面提醒。六個階層隨機分給入座的人、不重複，座位順序也隨機；每人起始英鎊、影響力、手牌照 `settings.json`；隱藏天命 1 張，從自己階層的天命隨機挑，沒有就從不屬於任何階層的挑，再沒有就沒有，同桌不發重複的。牌庫＝所有行動牌（一般牌與響應卡）依張數展開後洗牌，每桌一副。`startedAt` 是伺服器時間，只能寫一次，日落鐘之後從這裡算。
- 日出：每人領自己階層的薪水、抽 `drawPerSunrise` 張；牌庫不夠時先抽完剩下的，再把棄牌堆洗回成新牌庫接著抽，兩邊都空就不抽。手牌上限這時不管（黑夜結束時才棄，M8）。開局的同一筆寫入接著做第 1 回合日出（企劃 10/15 確認；`js/game.js` 的 `FIRST_SUNRISE_PAYS`）。
- 開局與每回合日出都是一筆多路徑寫入（`games`、`deals`、各人的 `private`、`hostOnly` 一起），由主持端算好再送出。防重複靠規則：`deals/{n}` 只能往上加、而且要等於該桌目前的回合；開局另外靠 `startedAt` 只能寫一次。兩台主持端同時開局或同時發同一回合，後到的那筆整筆被拒；被拒的一方等伺服器傳來現況（本機快取可能還是舊的），看到已經發過就不再發。
- 誰觸發日出發牌：主持端按「下一階段」從黑夜進到下一回合日出、而且是自己那筆交易成功的，接著自動發牌。任何主持端看到已開局、在日出、`deals/{n}` 小於目前回合時，畫面顯示「日出還沒發牌」與「補發」鈕（主持機在推進與發牌之間掛掉時，備援機用它補）。開局前、日出還沒發牌時，「下一階段」停用（畫面擋，規則不擋）。
- 推進用的交易只動 `tables/{n}`，局面在 `games/{n}`，兩者互不覆蓋。
- 開局後才加入該桌的人不入座：玩家畫面說明「本桌已開局」，主持端名單標「未入座」；不做中途入座。
- 隨機一律用 `crypto.getRandomValues`（Fisher–Yates，取餘數前丟掉尾段，不偏）；`js/game.js` 的純函式接受注入的亂數來源，測試用固定種子。網址帶 `?seed=<整數>` 時主持端改用固定種子（洗牌、隨機棄牌），只有模擬器認這個參數，正式專案一律忽略（`js/config.js` 的 `selectSeed`，有單元測試）。

### 白晝出牌（M5a）

- 輪流：白晝依座位順時針，一人一輪最多出 `maxPlaysPerTurn`（4）張，也可以不出（「結束這一輪」）；出滿自動換下一位。第 1 回合從 `startOrder`（主持端在第一張牌之前可以指定，沒設是座位 0）開始，之後每回合起始往下一位移。`turn.round` 不是目前的回合，就當這一回合的白晝還沒開始（第一位、0 張）。所有人都輪完＝白晝結束；主持端照舊手動按「下一階段」，沒輪完也能按，畫面提醒「還有 n 人沒出完」。每人 60 秒的提醒倒數只顯示，從各裝置看到輪到這個人的那一刻算起，不會自動換人。
- 請求：玩家把「我要出這張牌」（`type: play`，帶 `card`，要指定對象的牌帶 `target`，3 級連鎖帶 `chainTarget`）或「結束這一輪」（`type: pass`）寫進自己的 `/requests/{code}/{uid}`，序號 `seq` 一筆比一筆大。每人只有一個請求節點，畫面在主持端處理完之前不讓再送；沒處理就被蓋掉的舊請求不會被結算。玩家裝置不算任何結果。
- 結算：開著主持畫面的每台主持端都盯著請求（`store.js` 的 `startSettling`），看到 `seq` 大於該桌 `lastSeq/{uid}` 的就讀局面、手牌、牌庫，交給 `game.js` 的 `processRequest` 算，再一筆多路徑寫入（局面、該桌迷霧值、有變的手牌、牌庫與棄牌堆）。不合法的請求只寫 `lastSeq` 與本人的 `notice`（`{ seq, reason }`，原因的說明在 `game.js` 的 `REJECT_REASONS`），局面不動。
- 一張一般牌的順序：檢查（白晝、輪到他、出牌數未滿、牌在手上、不是響應卡、不是 `todo`、英鎊與影響力付得起、要的對象有給且合法）→ 付成本 → 算齒輪級數 → 依序套用效果（加上級數加成）→ 牌進棄牌堆 → 記罪孽、寫紀錄、更新輪次。前半是 `acceptPlay`（回傳已付成本、牌已離開手牌的局面，與待結算的 `pending`＝`{ by, seq, card, level, target, chainTarget }`），後半是 `resolvePlay`；M5a 兩步在同一筆寫入完成，M5b 會在兩步之間插入響應窗口，兩步之間的局面與 `pending` 都是純資料，可以單獨存。
- 效果：英鎊、影響力夾在 0 以上；抽牌沿用日出的 `draw`（牌庫不夠洗回棄牌堆）；棄牌由主持端亂數從手牌隨機挑，不夠就全棄；迷霧用 `advanceFog`、門檻取 `settings.fogThresholds`，新越過的門檻依序放進 `fogPending`，事件本身留給 M7。對象：`self` 出牌者、`all` 該桌入座的人、`others` 其他入座的人、`chosen` 請求裡的 `target`（同桌另一位入座的人，不能指定自己）、`role` 坐該階層的人（沒人坐就打空）。
- 齒輪連鎖：同一人同一輪內接著打出、齒輪相同的牌，第 n 張是 n 級，沒有齒輪或不同就從 1 級算。2 級：給出牌者自己的英鎊、影響力正數加倍（`@全體` 裡自己那一份也算）；3 級：照常結算，另外出牌者抽 2 張、`chainTarget`（同桌另一位）隨機棄 1 張；4 級：英鎊、影響力、抽牌、棄牌的數量全部加倍，含對別人的扣減，成本與迷霧不變。玩家畫面送出前就顯示「這張會是 n 級連鎖」，3 級要選人。
- 罪孽：出了分類是「犯罪」或「破壞」的牌，出牌者 `sin`＋1（M9 計分用）。
- 防兩台主持端互蓋：每筆改到局面的寫入（開局、日出、結算、指定起始玩家）都帶 `version＝讀到的＋1`，規則只收剛好＋1 的。兩台主持端同時結算同一筆請求，後到的整筆被拒；被拒的一方等伺服器的現況，看到 `lastSeq` 已到就放手，局面被別的寫入改過就重讀重算（最多 3 次），都不是就報錯。主持端先讀局面（`version`）再讀手牌與牌庫，中間有別的寫入時這次的寫入一定被拒，不會把新的手牌配上舊的局面寫回去。
- 推進與結算同時發生：推進的交易只動 `tables/{n}`；結算有迷霧效果時也寫 `tables/{n}/fog`，交易會因此重跑一次，迷霧值不會被蓋掉。規則不檢查結算時的階段：主持端在白晝最後一刻收下的請求，寫入可能在黃昏才到，照樣只算一次；下一回合輪次自然重來。

## 公開與私密分兩棵樹

資料庫的規則向下繼承：上層給了讀取權，下層收不回。`/rooms/{code}` 整棵是「知道房號就能讀」，所以**不能公開的東西不可以放在它底下**。

- 公開（`/rooms/{code}/games/{n}`）：座位順序、階層、英鎊、影響力、手牌**張數**、罪孽、牌庫與棄牌堆**張數**、白晝輪次、出牌紀錄（打出的牌本來就公開，這是公開樹裡唯一出現牌編號的地方）。同桌都看得到。
- 私密（`/private/{code}/{uid}`）：手牌內容、隱藏天命、請求被退回的原因（`notice`）。本人與主持端可讀，只有主持端可寫；玩家用 `watchPrivate` 訂閱自己那一筆。
- 只有主持端（`/hostOnly/{code}/{n}`）：牌庫順序（陣列順序＝抽牌順序）與棄牌堆。
- 請求（`/requests/{code}/{uid}`）：玩家要出哪張牌、指定誰。本人可寫可讀，該房主持端可讀整個 `/requests/{code}`；別的玩家讀不到（出牌前不洩漏手上有什麼）。
- 之後的未揭曉的票同樣放另一棵樹（例如 `/votes/{code}/{table}/{round}/{uid}`），規則寫成「本人與主持端可讀，揭曉後才由主持端抄到公開樹」。
- 陣列在資料庫裡是數字鍵的物件（`0`、`1`…），規則照這樣檢查；空陣列寫進去等於沒有這個欄位，讀回時當空的。

## 誰負責計算

主持端裝置。洗牌、發牌、揭曉、計分都由它算完後一次寫入；玩家的裝置只送出自己的選擇、訂閱結果。

## 卡牌資料從哪來、怎麼進遊戲

- 卡牌與數值是 `play/data/` 的七個 JSON 檔（設定、階層、行動牌、法案、事件、隱藏天命、教學提示 `tutorial.json`），跟網頁一起部署成靜態檔，不放資料庫。
- 瀏覽器由 `js/gamedata.js` 用 `fetch` 讀同源的 `./data/*.json`，用 `js/data.js` 的檢查；讀不到或有錯誤時畫面頂端顯示「卡牌資料有問題，請找工作人員」，開局與發牌停用。主持端用它洗牌、發牌、結算；玩家端用同一份檔把牌編號顯示成牌名與牌面文字。Node 測試注入讀檔函式，讀同一份檔。
- 正本是企劃填的試算表，一列一張，樣板在 `docs/data-templates/`。匯出的 CSV 用 `npm run data:import -- <資料夾>` 轉成 JSON，寫完自動檢查；`npm run data:check` 與 `npm test` 也會檢查。資料檔不手改，下次匯入會整個蓋掉。
- 牌的效果是結構化的物件（`{ op, target, amount }`），試算表用文字語法填（例如 `英鎊+5@自己；迷霧+3`），匯入時轉換；轉不了的標 `todo`、保留原文，先不結算。欄位與語法見 [`DATA-FORMAT.md`](DATA-FORMAT.md)。
- 格式定義與檢查在 `js/data.js`，是純函式，瀏覽器與 Node 共用；CSV 解析與轉換只在匯入時用，放在 `scripts/lib/`。
- 資料檔是公開的靜態檔，任何人都讀得到全部的牌與天命內容；要保密的是「誰拿到哪一張」，那放私密樹。
- 迷霧門檻：白晝結算讀 `settings.json` 的 `fogThresholds`；`js/rules.js` 的 30／60／90 只剩 `applyFog` 與 `advanceFog` 的預設值在用。

## 安全規則（`database.rules.json`）

- 預設全部不可讀寫；`/rooms` 不可列舉，房號就是門票。
- `/rooms/{code}`：已登入者可讀。
- `meta`：只能在不存在時建立，`hostUid` 必須是自己。
- `tables`：只有主持端可寫，並檢查階段、回合、迷霧值的範圍。
- `players/{uid}`：只能寫自己那一筆，房間必須存在，暱稱 1–12 字、桌號在範圍內。
- `hosts/{uid}`：只有現任主持端可寫，值只能是 `true` 或刪除；沒有人能把自己加進名單。
- `hostRequests/{uid}`：本人可寫（房間必須存在），本人或主持端可刪；內容只有 `requestedAt`。
- `presence/{uid}`：只能寫自己那一筆，值只能是 `true` 或刪除，房間必須存在。
- `games/{n}`：只有主持端可寫、不能刪；該桌必須存在，而且同一筆寫入裡 `deals/{n}` 也要在。每筆寫入的 `version` 都要剛好是舊值＋1（還沒有 `version` 時只能寫 1），不管改的是哪個欄位；沒帶、沒＋1 或跳號都整筆被拒。欄位逐一檢查（`startedAt` 只能寫一次；座位 `order` 0–5、`role` 是編號格式、英鎊與影響力與手牌張數與罪孽是 0 以上的整數；牌庫與棄牌堆張數同；`startOrder` 0–5，`turn` 存在後就不能改；`turn` 的 `round` 1 以上、`index` 0–6、`plays` 與 `level` 0 以上、`gear` 1–32 字；`fogMax` 與 `fogFired`、`fogPending` 的每一項是 0–100 的整數；`lastSeq/{uid}` 只能給入座的人、不往回、不超過他自己請求的 `seq`；出牌紀錄的 `by`、`target` 要是入座的人，`card` 是編號格式，`level` 1 以上），多的欄位一律拒絕。
- `deals/{n}`：只有主持端可寫、不能刪；整數、比舊值大、等於 `tables/{n}/round` 目前的值，而且該桌已開局（`games/{n}` 在）。
- `/private/{code}/{uid}`：本人可讀，該房主持端可讀整個 `/private/{code}`；只有主持端可寫。內容只有 `table`（必填，桌號在範圍內）、`hand`（牌編號的陣列）、`destiny`（天命編號）、`notice`（`seq` 1 以上的整數、`reason` 是小寫英文與 `-` 的原因代碼）；編號照 `js/data.js` 的 `ID_PATTERN`。
- `/hostOnly/{code}`：只有該房主持端可讀寫。每桌只有 `deck`、`discard` 兩個牌編號的陣列。
- `/requests/{code}/{uid}`：只有本人可寫（房間必須存在、不能刪），`seq` 要比舊的大；本人可讀，該房主持端可讀整個 `/requests/{code}`。內容只有 `seq`、`type`（`play` 或 `pass`）、`at`（必填）、`card`（`play` 必填，編號格式）、`target`、`chainTarget`（uid 格式），多的欄位拒絕。誰能出什麼牌由主持端結算時檢查，規則只管格式與寫入者。
- 主持端的判斷各處都一樣：`meta/hostUid` 是自己，或 `hosts/{uid}` 是 `true`。

## 身分

匿名登入，不收任何個人資料（玩家只輸入暱稱與桌號）。身分存在瀏覽器裡，關掉分頁再開還是同一個人；清除瀏覽器資料或換瀏覽器就是新的人。主持端離開主持畫面後，同一個身分用房號就能回來。網址加 `?slot=名稱` 可以讓同一個瀏覽器的不同分頁當不同的人，開發與測試用。

## 已知限制

- 同時連線上限 100，每支手機、每個分頁、投影電腦各算 1。
- 沒有雲端函式：所有主持端都離線時，各桌就停在原地；規則只能檢查格式，算得對不對要信任主持端。
- 備援主持機必須在開場前由現任主持端核准。主持機掛掉之後才來申請的，沒有人能核准；主持端清除瀏覽器資料後就是新的身分，同樣要重新申請。
- 主持名單沒有移除的畫面（規則允許主持端刪除），核准前務必核對確認碼。確認碼只防認錯人，不是密碼。
- 上線狀態每個身分只有一筆：同一個身分開兩個分頁時算同一個人；斷線要等伺服器察覺連線中斷才會標示，網路突然消失（不是正常關閉）時會比較慢，實際多久要用實機量。
- import map 需要 iOS Safari 16.4 以上／Chrome 89 以上；更舊的瀏覽器會看到「請更新」的說明。
- 暱稱長度以 UTF-16 計，表情符號多半一個算 2。
- 房間不會自動刪除，活動後要另外清；`/private`、`/hostOnly` 兩棵樹也要一起清。
- 規則要求英鎊、影響力不小於 0：白晝結算已經夾在 0 以上；之後的結算（黃昏、黑夜、事件）也要夾，否則整筆寫入會被拒。
- `database.rules.json` 加了 `version` 守門與新的樹，正式專案的規則要跟新版網頁一起換：只推網頁不發布規則，新版寫不進去（舊規則拒絕 `version`、`turn` 等新欄位與 `/requests`）；只發布規則不推網頁，舊版網頁的開局與發牌會被拒（沒帶 `version`）。兩個一起做完，開一間新房走一次開局到白晝出牌。舊局面（沒有 `version`）第一次被新版寫入時從 1 開始。
- 規則不檢查結算時的階段，也不檢查結算算得對不對（例如成本有沒有付、效果有沒有照牌面）：沒有雲端函式，只能信任主持端。
- 主持端在每個請求上會多讀幾次資料庫（各入座玩家的手牌、牌庫）；六桌同時出牌時的流量要在容量演練（M12）實測。
- 局面不能從畫面刪掉重開；要重來就開新房。第二場（M9）的重置要另外設計（例如局面多一層「第幾場」）。
- 開局後換桌或離開房間的人，座位照舊留著；離開的人在畫面上顯示「已離開房間」，日出照樣領薪抽牌。
