# 多人連線版（開發中）

「一日英國人：女皇陛下萬歲！」的多人連線網頁。這個資料夾就是之後要部署的靜態內容，全部用相對路徑，不引用任何外部資源。

目前做到黃昏投票：主持端開房 → 玩家用房號加入 → 主持端按那一桌的「開始」，每人拿到階層、隱藏天命、手牌、英鎊與影響力 → 主持端按「下一階段」，同桌所有人的畫面一起更新，每回合日出自動領薪抽牌 → 白晝依座位輪流出牌，別人出一般牌時其他人有 5 秒可以打響應卡，主持端自動結算成本、效果、齒輪連鎖與響應 → 黃昏翻開一張法案，每人暗中選贊成或反對並押影響力（或棄權），全員送出後 3 秒揭曉，主持端自動結算出價與法案效果。備援裝置可以申請成為主持端，畫面會顯示自己的連線狀態與誰在線上。架構說明見 [`docs/ARCHITECTURE.md`](../docs/ARCHITECTURE.md)，接下來要做的事見 [`docs/MILESTONES.md`](../docs/MILESTONES.md)。

## 需要什麼

- Node.js 22 以上（開發時用 24）。
- Java 21 以上：只有資料庫模擬器需要，跑單元測試不需要。
- 第一次啟動模擬器時會下載資料庫模擬器（約 35 MB）到使用者快取目錄，需要網路；之後可離線。

不想把 Java 裝進系統的話，可以放一份在專案裡（`.tools/` 不進版控）：到 <https://adoptium.net/temurin/releases/?version=21> 下載對應作業系統的 JRE 壓縮檔，核對頁面上的 SHA-256 後解壓：

```sh
mkdir -p .tools/jre
tar -xzf OpenJDK21U-jre_*.tar.gz -C .tools/jre --strip-components=1
```

`scripts/with-java.sh` 會依序找 `$JAVA_HOME`、PATH 上的 `java`、`.tools/jre`，都沒有就停下來說明。

## 本機跑起來

以下指令都在專案根目錄執行。

```sh
npm install
npm run dev
```

看到 `All emulators ready` 後開 <http://127.0.0.1:5050/>。按 Ctrl+C 結束；模擬器的資料只在記憶體裡，關掉就清空。

在本機開啟時只連本機的模擬器，專案代號是 `demo-one-day-briton`（`demo-` 開頭代表不對應任何雲端專案），不需要帳號、不需要登入。連正式專案見下方「正式環境」。

## 用幾個分頁扮不同的人

同一個瀏覽器的分頁預設共用同一個身分。網址加上 `?slot=名稱` 就是另一個人：

| 分頁 | 網址 |
|---|---|
| 主持端 | `http://127.0.0.1:5050/` |
| 玩家一 | `http://127.0.0.1:5050/?slot=p1` |
| 玩家二 | `http://127.0.0.1:5050/?slot=p2` |

主持端按「開新房」拿到房號，兩個玩家分頁輸入房號、暱稱、桌號加入，再回主持端開局、推進（見下一節）。重新整理任何一個分頁，都會回到同一個房間、同一個身分。

### 開局與日出

1. 主持端每桌的卡片列出入座候選與人數。按「開始」：0 人或超過 6 人不能開（按鈕停用、寫原因）；少於 3 人可以開，但會提醒。
2. 開局後，入座的人隨機分到座位與階層、各拿 1 張隱藏天命與起始手牌，同時做第 1 回合日出（領薪、抽牌）。以目前的資料，每人英鎊 15、影響力 3、手牌 6。
3. 玩家分頁不用重新整理，就會看到自己的階層（使命、特權）、天命、手牌、英鎊、影響力，以及同桌其他人的階層、英鎊、影響力與手牌張數（看不到別人的手牌與天命）。開局前顯示「等待主持端開局」；開局後才加入的人顯示「本桌已開局」，主持端標「未入座」。
4. 開局前不能按「下一階段」。開局後一直按到下一回合的日出，按的那台主持端接著自動發牌（每人領薪、抽 2 張）；第 2 回合日出後每人英鎊 20、手牌 8。
5. 主持機在推進與發牌之間掛掉時，任何主持端都會看到「日出還沒發牌」與「補發」；發完之前「下一階段」停用。兩台同時按也只會發一次。

卡牌資料（`data/*.json`）讀不到或檢查有錯誤時，畫面頂端顯示「卡牌資料有問題，請找工作人員」，開局與發牌都停用；先跑 `npm run data:check` 看錯在哪裡。

### 白晝出牌

1. 第 1 回合、還沒有人出牌之前，主持端每桌的卡片有「第 1 回合的起始玩家」選單與「指定起始玩家」（預設座位 1，也就是座位順序的第一位）；之後每回合起始玩家往下一位移。
2. 主持端按「下一階段」到白晝。輪到的玩家畫面寫「輪到你出牌」，手牌每張有「出牌」；付不起、響應卡（要在別人出牌時打，見下一節）、效果還沒做好的牌停用並寫原因。其他人看到「輪到 ○○」。每人有 60 秒的提醒倒數，只是提醒，不會自動換人。
3. 按「出牌」後先看「這張會是 n 級連鎖」：同一輪接著出齒輪相同的牌，第 2 張起是 2、3、4 級（2 級給自己的英鎊、影響力加倍；3 級另外抽 2 張、指定一人隨機棄 1 張；4 級數量全部加倍）。要指定對象的牌、3 級連鎖都要先選人，再按「確定出牌」。
4. 送出後畫面顯示「結算中…」，開著主持畫面的主持端自動檢查（不用按任何鈕），接下這張牌（成本先付、牌離開手牌），開 5 秒的響應窗口（見下一節），窗口結束才結算效果；同桌所有人不用重新整理就看到英鎊、影響力、手牌張數與「最近出牌」。不合法的請求不會結算，只有本人看到「沒有出成：原因」。
5. 一輪最多出 4 張，出滿自動換下一位；也可以隨時按「結束這一輪」（一張都不出也可以）。主持端每桌顯示輪到誰、這一輪出了幾張、連鎖狀態、還有幾人沒出完與最近的出牌。大家都輪完時畫面寫「大家都出完了」；主持端沒輪完也能按「下一階段」進黃昏，畫面會先提醒還有幾人沒出完。

### 響應卡

1. 別人每打出一張一般牌，同桌其他入座的人畫面出現「○○ 打出「X」（分類）——n 秒內可以響應」與倒數（`data/settings.json` 的 `responseSeconds`，目前 5 秒，照伺服器時間算）。手上的響應卡多一個「響應」鈕；分類不合、付不起、時間過了的停用並寫原因。
2. 按「響應」後畫面顯示「已送出，等結算」。先到先算（以伺服器收到的時間為準），一張牌最多被響應一次；晚一步的人看到「響應沒有成功：別人先響應了這張牌」。
3. 有人響應時主持端馬上結算：原牌先照常結算，再結算響應卡（「@出牌者」是原出牌者、「@自己」是響應者，響應卡不吃齒輪加成）。響應卡是「抵銷」時，原牌的效果與連鎖加成都不發生，但成本照付、照樣算出了一張、連鎖斷掉、犯罪或破壞照記罪孽。「最近出牌」寫「被 ○○ 以「Y」響應」，抵銷再加「被抵銷」。
4. 沒人響應時，倒數到 0 後畫面寫「響應時間到了，等主持端結算」，主持端再等 1 秒（給還在路上的響應）就自動結算，前後約 6 秒。
5. 窗口開著時，出牌的人畫面寫「等其他人響應 n 秒」，出牌與「結束這一輪」停用；主持端那一桌顯示「等響應：…還有 n 秒」，「下一階段」停用並寫原因。響應卡不算出牌數、不影響任何人的齒輪連鎖；分類是「犯罪」或「破壞」的響應卡，打的人也記 1 點罪孽。
6. 用固定手牌試：主持端網址加 `?seed=17`、兩人一桌開局，座位順序第一位（先出牌）手上有「銀行貸款」（交易）「紡織廠加班」（生產）「線民情報」（查緝），第二位有兩張「跟風投機」（可回應交易）與「王室召見」（抵銷查緝）：依序出這三張，就能看到響應、沒人響應時間到、抵銷。

### 黃昏：法案表決

1. 大家都出完了，主持端按「下一階段」進黃昏。開著主持畫面的主持端自動翻開一張法案（不用按）：第一次進黃昏時把全部法案洗成這一桌的一疊，每個黃昏抽最上面一張；抽完時把還沒通過的洗回去再抽；全都通過了就「今天議會休會」，這一回合不投票，主持端可以直接進下一階段。
2. 玩家畫面出現法案卡（名稱、年代、說明）、「已送出 n／m 人」與 2 分鐘的提醒倒數（只是提醒，不會自動揭曉）。選「贊成」「反對」或「棄權」，選邊的人再選影響力出價（0 到自己目前的影響力），按「送出」：畫面寫「已送出：贊成 2（揭曉前可以改）」，揭曉前可以改成別的再送一次，以最後一次為準。沒送出算棄權。
3. 全員送出後，所有畫面寫「大家都送出了，n 秒後揭曉」（`data/settings.json` 的 `duskRevealSeconds`，目前 3 秒，照伺服器時間算），倒數中還可以改票；倒數結束主持端再等 1 秒（給還在路上的票）就揭曉，前後約 4 秒。主持端也可以按「提前揭曉」：投票馬上截止，沒送出的人算棄權，約 1 秒後揭曉。
4. 揭曉：贊成與反對各自加總出價，贊成大於反對才通過，平手不通過。選邊的人照出價付影響力（不論輸贏），先付出價、再套法案效果（通過照「通過」、不通過照「不通過」；指定階層的效果打到坐那個階層的人，沒人坐就打空）。所有畫面不用重新整理就看到：通過與否、兩邊總和、每個人的選邊與出價（沒送出的寫「沒送出（算棄權）」）；玩家另外看到自己付了多少、結算後的英鎊與影響力，選邊與結果一致時寫「站在結果這一邊（議會之聲 +1）」。
5. 揭曉前，主持端那一桌的「下一階段」停用並寫原因；揭曉後才能進黑夜。黑夜時玩家畫面還看得到這一回合的結果。
6. 用固定法案試：主持端網址加 `?seed=7`、三人一桌開局、白晝大家直接「結束這一輪」：第 1 回合翻到「八小時工作法」、第 2 回合翻到「十小時工作法案」，座位上的階層是蒸汽工業大亨、憲章工聯與罷工領袖、皇家學會與神祕學通靈師（誰坐哪一個仍是隨機的）。第 1 回合全員送出（例如贊成 2、反對 1、棄權）看倒數揭曉；第 2 回合只讓一個人送出，主持端按「提前揭曉」。

### 固定手牌（只有模擬器）

主持端網址加 `?seed=<整數>`（例如 `http://127.0.0.1:5050/?seed=3`），開局洗牌、隨機棄牌就用固定種子，每次開出來的牌一樣，方便照著同一副牌測試畫面；座位 1 的手牌只看種子，誰坐座位 1 仍是隨機的。正式專案不認這個參數。

### 試備援主持

再開一個分頁當備援裝置：`http://127.0.0.1:5050/?slot=b`。

1. 在備援分頁的「主持端」卡片輸入房號，按「以主持端進入」。畫面會顯示 4 碼確認碼與「等待主持端核准」。
2. 回主持端分頁，「主持端」卡片會列出這筆申請與同一組確認碼；核對相同後按「核准」（或「拒絕」）。
3. 備援分頁自動切到主持畫面，之後兩個分頁都能按「下一階段」；同時按也只會前進一步。
4. 主持端分頁按「離開」回首頁，再用同一個房號「以主持端進入」，會直接回到主持畫面。

關掉玩家分頁，主持畫面會把那位玩家標成「離線」；兩個主持分頁都關掉時，玩家畫面會顯示「主持端目前離線」。

## 正式環境

`js/config.js` 有本機模擬器與正式專案兩組設定，依開啟頁面的網址選一組：

| 網址 | 連到 |
|---|---|
| 帶 `?env=emu` | 本機模擬器 |
| 帶 `?env=prod` | 正式專案 |
| 都沒帶，主機是 `localhost`、`127.0.0.1` 或 `::1` | 本機模擬器 |
| 都沒帶，其他主機 | 正式專案 |

推上 GitHub Pages 後的網址是 <https://kiresakura.github.io/one-day-briton/play/>，不用加參數就連正式專案。

本機加 `?env=prod`（例如 `http://localhost:5050/?env=prod`，可以再加 `&slot=p1`）也會連正式專案，開的房、加入的玩家都**寫進正式資料庫**，而且房間不會自動刪除，只在驗收時用。請用 `localhost` 開：正式專案的已授權網域有 `localhost`，沒有 `127.0.0.1`。

設定裡的 `apiKey` 等值是公開的識別碼，不是密碼；誰能讀寫由根目錄的 `database.rules.json` 決定，發布方式見 [`docs/ARCHITECTURE.md`](../docs/ARCHITECTURE.md) 的「環境」。

## 測試

```sh
npm test            # 卡牌資料檢查＋純函式（階段、迷霧值、房號、暱稱、確認碼、環境選擇、資料格式、CSV 匯入、開局與發牌、白晝出牌與結算、響應卡、黃昏投票與揭曉），不需要 Java
npm run test:sync   # 啟動模擬器，用 js/store.js 測同步與安全規則（含私密資料與牌庫的讀寫權限、開局與發牌不重複、出牌請求的權限、結算與 version 守門、響應窗口與時間到、票的讀寫權限、倒數揭曉與提前揭曉）
npm run test:all    # 兩者都跑
npm run data:check  # 只檢查 play/data/ 的卡牌資料檔
npm run data:import -- <CSV 資料夾>   # 試算表匯出的 CSV 轉成 play/data/，寫完自動檢查
```

`test:sync` 會印出許多 `permission_denied` 警告，那是「被拒絕才算通過」的測試留下的，以最後的統計為準。

## 連接埠

全部只綁 `127.0.0.1`，設定在根目錄的 `firebase.json`。

| 用途 | 連接埠 |
|---|---|
| 網頁（hosting） | 5050 |
| 匿名登入（auth） | 9099 |
| 資料庫（database） | 9000 |
| 模擬器控制（hub） | 4400 |
| 模擬器記錄（logging） | 4500 |

網頁不用預設的 5000，因為 macOS 的 AirPlay 接收器會佔用它。改了 9099 或 9000 的話，`js/config.js` 要跟著改。

## 自行託管的 SDK

`vendor/firebase/` 裡的三個檔案來自 npm 的 `firebase` 套件（版本與雜湊見 `vendor/firebase/VERSION.txt`，授權為 Apache-2.0）。官方檔案彼此之間是用 `https://www.gstatic.com/…` 的網址互相匯入，複製時已改寫成相對路徑，所以頁面只會向自己的主機要檔案。`firebase-app.js` 裡還留有兩處該網址的字串，那是 SDK 用來標示自己名稱的常數，不會發出請求。

`js/store.js` 寫的是 `firebase/app` 這種模組名稱：瀏覽器靠 `index.html` 裡的 import map 對到 `vendor/firebase/`，Node 測試則用 `node_modules` 裡的同一版套件。

升級 SDK 時改 `package.json` 的版本、`npm install`，再重新產生：

```sh
npm run vendor
```
