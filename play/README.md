# 多人連線版（開發中）

「一日英國人：女皇陛下萬歲！」的多人連線網頁。這個資料夾就是之後要部署的靜態內容，全部用相對路徑，不引用任何外部資源。

目前做到一場的終局與計分（兩場制還沒做）：主持端開房 → 玩家用房號加入 → 主持端按那一桌的「開始」，每人拿到階層、隱藏天命、手牌、英鎊與影響力 → 主持端按「下一階段」，同桌所有人的畫面一起更新，每回合日出自動領薪抽牌 → 白晝依座位輪流出牌，別人出一般牌時其他人有 5 秒可以打響應卡，主持端自動結算成本、效果、齒輪連鎖與響應 → 黃昏翻開一張法案，每人暗中選贊成或反對並押影響力（或棄權），全員送出後倒數約 4 秒揭曉（3 秒＋主持端的 1 秒緩衝），主持端自動結算出價與法案效果 → 黑夜每人暗中選豪賭（選賭到第幾層）、分贓或睡覺，全員送出後倒數約 4 秒揭曉，主持端擲骰結算；手牌超過上限的人在黑夜挑要棄的牌，下一回合日出先棄再發牌 → 每回合日出翻一張一般事件，迷霧值越過 30／60／90 時觸發迷霧事件，全桌都看得到 → 開局 75 分鐘後（日落鐘）、第 12 回合，或主持端按了「這回合結束後算分」，那一回合黑夜結束就算分，所有畫面看到結算與名次。備援裝置可以申請成為主持端，畫面會顯示自己的連線狀態與誰在線上。架構說明見 [`docs/ARCHITECTURE.md`](../docs/ARCHITECTURE.md)，接下來要做的事見 [`docs/MILESTONES.md`](../docs/MILESTONES.md)。

## 需要什麼

- Node.js 22 以上（開發時用 24）。
- Java 21 以上：只有資料庫模擬器需要，跑單元測試不需要。
- 第一次啟動模擬器時會下載資料庫模擬器（約 35 MB）到使用者快取目錄，需要網路；之後可離線。

不想把 Java 裝進系統的話，可以放一份在專案裡（`.tools/` 不進版控）：到 <https://adoptium.net/temurin/releases/?version=21> 下載對應作業系統的 JRE 壓縮檔，核對頁面上的 SHA-256 後解壓：

```sh
mkdir -p .tools/jre
tar -xzf OpenJDK21U-jre_*.tar.gz -C .tools/jre --strip-components=1
```

`scripts/with-java.sh` 會依序找 `$JAVA_HOME`、PATH 上的 `java`、`.tools/jre`，都沒有就停下來說明。

## 本機跑起來

以下指令都在專案根目錄執行。

```sh
npm install
npm run dev
```

看到 `All emulators ready` 後開 <http://127.0.0.1:5050/>。按 Ctrl+C 結束；模擬器的資料只在記憶體裡，關掉就清空。

在本機開啟時只連本機的模擬器，專案代號是 `demo-one-day-briton`（`demo-` 開頭代表不對應任何雲端專案），不需要帳號、不需要登入。連正式專案見下方「正式環境」。

## 主持端畫面怎麼看

筆電 1280×800 為主（平板 1024 寬改成 2 欄、可以捲動）。版面照畫面規格；每個按鈕的作用與能不能按的條件跟改版前一樣。

- **開房／接手**：首頁按「開房／接手房間」。左邊「開一個新房間」：桌數（6 桌）、日落鐘（照卡牌資料的設定）目前都是固定的，只顯示不能改；場次寫一行說明（兩場制：第 1 場結束後，在主持畫面各桌按「開第 2 場」，同一間房接著打）；按「建立房間」。右邊「接手已經開的房間」：輸入房號送出備援主持申請（見「試備援主持」）。
- **頂列**：房號、各狀態的桌數（可推進／等待中／待判定／未開始，第 2 場也算完分的桌另列「已結束」）、主持端幾台在線、「備援主持申請 n」（點開核對確認碼後核准）、「離開」。有桌子到了第 1 場結束之後，下面多一行「第 1 場結束／第 2 場進行中／第 2 場結束」各幾桌，旁邊是「已結束的桌全部開第 2 場」（見「兩場制：開第 2 場」）。
- **桌卡**（6 桌固定 3×2，1280×800 內不用捲動），由上而下：
  - 色帶：桌號、「第 2 場・第 3 回合・白晝」（場次、回合、階段）、「最後一回合」、迷霧值（已觸發的刻度變粗）。
  - 狀態列：下一步要做什麼或在等誰，文字＋圖示；有倒數的用倒數圈（響應窗口、提醒倒數、揭曉倒數）。「✓ 可以按下一階段」的桌外框是金色。
  - 玩家表：玩家・階層、英鎊、影響、手牌、罪孽，最後一欄照階段（起始玩家、出牌中、可響應、表決、黑夜結果、要棄幾張）。名字或階層太長時「…」加點線底線，點一下彈出全文（名字、階層、座位），點別處關閉。
  - 今日事件或法案（黑夜寫手牌超過上限的人）：最多兩行，太長一樣點一下看全文。
  - 底部：日落鐘、牌庫／棄牌；「紀錄」「這回合結束後算分」；右邊是這一步的按鈕（開始、補發、提前揭曉、下一階段、展開結算明細、開第 2 場、開始第 2 場）。按鈕不能按時，下面寫現在真正的原因。
- **紀錄**：每桌的「紀錄」開右側抽屜，照回合分段、新的在上：出牌（含響應）、今日事件與迷霧事件、黃昏與黑夜的揭曉結果。第 2 場的紀錄可以切換看第 1 場（只讀）。
- **結算明細**：終局的桌按「展開結算明細」開右側抽屜，在這裡判定「判定」空白的天命。第 2 場結束的桌分三段：兩場合計、第 2 場明細（可以判定）、第 1 場明細（只讀、已鎖定）。
- 抽屜按「×」、點旁邊的暗處或按 Esc 關閉，鍵盤 Tab 只在抽屜裡轉；別人的動作讓畫面更新時，開著的抽屜、彈出的全文、備援申請面板與捲動位置都不會被關掉。

## 玩家畫面怎麼操作

手機直式為主（390×844，最小 360 寬）。版面與配色照畫面規格：每個階段換一種色調（日出、白晝、黃昏、黑夜、終局），手牌一律是羊皮紙卡面。

### 加入

- 房號照主持人投影上的 6 碼輸入，畫面分成 6 格，其實是一個輸入框：可以整串貼上，空白會去掉，英文不分大小寫。
- 名字最多 12 個字，同桌的人看得到。
- 自己選第 1–6 桌（選實際坐的那一桌）。
- 「加入」不能按時，原因直接寫在按鈕上（例如「再輸入 2 碼才能加入」）。
- 重連：斷線或關掉網頁時，用同一支手機的**同一個瀏覽器**重新打開同一個網址，會自動回到同一桌、同一個座位（登入身分與房號記在這個瀏覽器裡）。無痕視窗、換瀏覽器或清掉網站資料就回不去，只能重新加入（開局後才加入的人不入座）。
- 選錯桌：開局前在「行動」或「階層」分頁按「離開房間」，再用同一個房號重新加入。

### 畫面結構

由上而下：

- 階段標頭：場次（目前固定「第 1 場」）、桌號與回合、連線狀態（「已連線」或「斷線」）、階段名稱、迷霧值（「34／100」，已觸發的 30／60／90 刻度變酒紅粗體）。
- 主要動作區、手牌（左右滑動）、動作列（這一步要按的鈕，不能按時寫原因）。
- 分頁列：行動／階層／同桌／紀錄／天命・按住看。

斷線超過 1 秒，畫面頂端出現「連線中斷，正在重新連線…」，標頭寫「斷線」；連回來就自動恢復，不用重新整理。

### 分頁

- **行動**：這一個階段要做的事。日出看今日事件；白晝輪到你時點一張牌選取（再點一次或按「取消選牌」取消），動作列寫「這張會是 n 級連鎖」，要指定對象的牌在動作列選人，再按「確定出牌」或「結束這一輪」；別人出牌時，能響應的牌亮著、其他牌淡化並寫原因，按「打出響應」。黃昏選贊成／反對／棄權、用「−」「＋」調出價，按動作列的「送出」；黑夜三選一（豪賭可以直接點第幾層）。送出後收成一行，按「修改」可以改。
- **階層**：自己的階層徽章、英鎊、影響力、罪孽、使命與特權；底下有房號與「離開房間」。
- **同桌**：照座位列出每個人的暱稱（全文）、階層、英鎊、影響力、手牌張數、罪孽；輪到誰標「▶」。
- **紀錄**：照回合分段、新的在上面：出牌（含響應）、今日事件與迷霧事件、黃昏與黑夜的揭曉結果；可以只看「出牌」或「事件」。
- **天命・按住看**：按住才顯示自己的隱藏天命與達成條件，放開就收起來（旁人看不到）；終局前只有自己的手機有這份資料。終局後全桌的天命在結算畫面按「看全桌天命」。

需要你動作時（輪到你出牌、響應窗口、黃昏開票、黑夜開始、要選棄牌），畫面自動切回「行動」分頁。別人的動作讓畫面更新時，手牌的捲動位置、選好的牌、出價、目前的分頁、按住中的天命都會留著。

## 用幾個分頁扮不同的人

同一個瀏覽器的分頁預設共用同一個身分。網址加上 `?slot=名稱` 就是另一個人：

| 分頁 | 網址 |
|---|---|
| 主持端 | `http://127.0.0.1:5050/` |
| 玩家一 | `http://127.0.0.1:5050/?slot=p1` |
| 玩家二 | `http://127.0.0.1:5050/?slot=p2` |

主持端在首頁按「開房／接手房間」、再按「建立房間」拿到房號，兩個玩家分頁輸入房號、暱稱、桌號加入，再回主持端開局、推進（見下一節）。重新整理任何一個分頁，都會回到同一個房間、同一個身分。

### 開局與日出

1. 主持端每桌的桌卡寫「等玩家加入・已加入 n 人」，列出加入的人（已連線／離線）。按「開始」：0 人或超過 6 人不能開（按鈕停用、下面寫原因）；少於 3 人可以開，但狀態列會提醒。
2. 開局後，入座的人隨機分到座位與階層、各拿 1 張隱藏天命與起始手牌，同時做第 1 回合日出（領薪、抽牌，接著翻第 1 回合的一般事件，見下面「事件」）。以目前的資料，領薪抽牌後每人英鎊 15、影響力 3、手牌 6，再照翻到的事件增減。
3. 玩家分頁不用重新整理，就會看到自己的階層（使命、特權）、天命、手牌、英鎊、影響力，以及同桌其他人的階層、英鎊、影響力與手牌張數（看不到別人的手牌與天命）。開局前顯示「等待主持端開局」；開局後才加入的人顯示「本桌已開局」，主持端標「未入座」。
4. 開局前不能按「下一階段」。開局後一直按到下一回合的日出，按的那台主持端接著自動發牌（每人領薪 5 英鎊、抽 2 張），再翻這一回合的一般事件。
5. 主持機在推進與發牌之間掛掉時，任何主持端都會看到「日出還沒發牌」與「補發」；發完之前「下一階段」停用。兩台同時按也只會發一次。

卡牌資料（`data/*.json`）讀不到或檢查有錯誤時，畫面頂端顯示「卡牌資料有問題，請找工作人員」，開局與發牌都停用；先跑 `npm run data:check` 看錯在哪裡。

### 白晝出牌

1. 第 1 回合、還沒有人出牌之前，主持端每桌的桌卡有「第 1 回合起始玩家」選單與「指定」（預設座位 1，也就是座位順序的第一位）；之後每回合起始玩家往下一位移。
2. 主持端按「下一階段」到白晝。輪到的玩家畫面寫「輪到你出牌」（出牌順序那一排標「▶」、酒紅外框），手牌可以點選；付不起、響應卡（要在別人出牌時打，見下一節）、效果還沒做好的牌是虛線框、淡化，底下寫原因。其他人看到「輪到 ○○ 出牌」。每人有 60 秒的提醒倒數（倒數圈），只是提醒，不會自動換人。
3. 點一張牌，動作列先寫「這張會是 n 級連鎖」：同一輪接著出齒輪相同的牌，第 2 張起是 2、3、4 級（2 級給自己的英鎊、影響力加倍；3 級另外抽 2 張、指定一人隨機棄 1 張；4 級數量全部加倍）。要指定對象的牌、3 級連鎖都要先在動作列選人，再按「確定出牌」。
4. 送出後畫面顯示「結算中…」，開著主持畫面的主持端自動檢查（不用按任何鈕），接下這張牌（成本先付、牌離開手牌），開 5 秒的響應窗口（見下一節），窗口結束才結算效果；同桌所有人不用重新整理就看到英鎊、影響力、手牌張數與「最近出牌」。不合法的請求不會結算，只有本人看到「沒有出成：原因」。
5. 一輪最多出 4 張，出滿自動換下一位；也可以隨時按「結束這一輪」（一張都不出也可以）。主持端那一桌的狀態列寫「在等 ○○ 出牌」（第幾位、這一輪出了幾張、還有幾人沒出完）與提醒倒數圈，玩家表的狀態欄標「▶ 出牌中」「出完了」；最近的出牌在那一桌的「紀錄」裡。大家都輪完時畫面寫「大家都出完了」；主持端沒輪完也能按「下一階段」進黃昏（狀態列寫「下一階段隨時可以按」）。

### 響應卡

1. 別人每打出一張一般牌，同桌其他入座的人畫面出現「可以響應」、「○○ 打出「X」（分類）」與倒數圈（`data/settings.json` 的 `responseSeconds`，目前 5 秒，照伺服器時間算）。能打的響應卡亮著（第一張先選好），其他牌淡化並寫原因（分類不合、付不起、時間過了…）；動作列寫要打出哪一張。
2. 按「打出響應」後畫面顯示「已送出，等結算」。先到先算（以伺服器收到的時間為準），一張牌最多被響應一次；晚一步的人看到「響應沒有成功：別人先響應了這張牌」。
3. 有人響應時主持端馬上結算：原牌先照常結算，再結算響應卡（「@出牌者」是原出牌者、「@自己」是響應者，響應卡不吃齒輪加成）。響應卡是「抵銷」時，原牌的效果與連鎖加成都不發生，但成本照付、照樣算出了一張、連鎖斷掉、犯罪或破壞照記罪孽。「最近出牌」寫「被 ○○ 以「Y」響應」，抵銷再加「被抵銷」。
4. 沒人響應時，倒數到 0 後畫面寫「響應時間到了，等主持端結算」，主持端再等 1 秒（給還在路上的響應）就自動結算，前後約 6 秒。
5. 窗口開著時，出牌的人畫面寫「等其他人響應 n 秒」，出牌與「結束這一輪」停用；主持端那一桌的狀態列是倒數圈＋「等響應」（誰打出哪一張），玩家表標「出牌・等響應」「可響應」，「下一階段」停用、下面寫「響應結算後才能按」。響應卡不算出牌數、不影響任何人的齒輪連鎖；分類是「犯罪」或「破壞」的響應卡，打的人也記 1 點罪孽。
6. 用固定手牌試：主持端網址加 `?seed=17`、兩人一桌開局（第 1 回合的一般事件是「倫敦交易所黑色星期五」，坐蒸汽工業大亨的人英鎊少 4），座位順序第一位（先出牌）手上有「銀行貸款」（交易）「紡織廠加班」（生產）「線民情報」（查緝），第二位有兩張「跟風投機」（可回應交易）與「王室召見」（抵銷查緝）：依序出這三張，就能看到響應、沒人響應時間到、抵銷。

### 黃昏：法案表決

1. 大家都出完了，主持端按「下一階段」進黃昏。開著主持畫面的主持端自動翻開一張法案（不用按）：第一次進黃昏時把全部法案洗成這一桌的一疊，每個黃昏抽最上面一張；抽完時把還沒通過的洗回去再抽；全都通過了就「今天議會休會」，這一回合不投票，主持端可以直接進下一階段。
2. 玩家畫面出現法案卡（名稱、年代、說明）、「已送出 n／m 人」與 2 分鐘的提醒倒數（只是提醒，不會自動揭曉）。選「贊成」「反對」或「棄權」，選邊的人再用「−」「＋」調影響力出價（0 到自己目前的影響力），按動作列的「送出：贊成・出價 2」：表決收成一行「✓ 贊成 2」，揭曉前按「修改」可以改成別的再送一次，以最後一次為準。沒送出算棄權。
3. 全員送出後，所有畫面寫「大家都送出了，n 秒後揭曉」，倒數中還可以改票。倒數照實際揭曉的時間：截止（`data/settings.json` 的 `duskRevealSeconds`，目前 3 秒，照伺服器時間算）之後主持端再等 1 秒（給還在路上的票）才揭曉，所以從 4 開始倒數；到 0 還沒揭曉寫「揭曉中…」。玩家畫面另有大數字倒數圈。主持端也可以按「提前揭曉」：投票馬上截止，沒送出的人算棄權，畫面寫「已截止」，約 1 秒後揭曉。
4. 揭曉：贊成與反對各自加總出價，贊成大於反對才通過，平手不通過。選邊的人照出價付影響力（不論輸贏），先付出價、再套法案效果（通過照「通過」、不通過照「不通過」；指定階層的效果打到坐那個階層的人，沒人坐就打空）。所有畫面不用重新整理就看到：通過與否、兩邊總和、每個人的選邊與出價（沒送出的寫「沒送出（算棄權）」）；玩家另外看到自己付了多少、結算後的英鎊與影響力，選邊與結果一致時寫「站在結果這一邊（議會之聲 +1）」。
5. 揭曉前，主持端那一桌的「下一階段」停用並寫原因；揭曉後才能進黑夜。黑夜時玩家畫面還看得到這一回合的結果。
6. 用固定法案試：主持端網址加 `?seed=7`、三人一桌開局、白晝大家直接「結束這一輪」：第 1 回合翻到「遺產稅法案」、第 2 回合翻到「印度政府法」（M7 起開局多洗一疊一般事件，用掉的亂數變多，翻到的法案跟 M6 時不同；這兩張是用純函式照同一條亂數算出來的），座位上的階層是蒸汽工業大亨、憲章工聯與罷工領袖、皇家學會與神祕學通靈師（誰坐哪一個仍是隨機的）。第 1 回合全員送出（例如贊成 2、反對 1、棄權）看倒數揭曉；第 2 回合只讓一個人送出，主持端按「提前揭曉」。

### 黑夜：豪賭、分贓、睡覺

1. 黃昏揭曉後（或議會休會時），主持端按「下一階段」進黑夜。開著主持畫面的主持端自動開始黑夜（不用按）。第 1 回合的玩家畫面先寫黑夜的教學提示（`data/tutorial.json` 裡階段是黑夜的那幾則）。
2. 玩家畫面出現三個選項、「已送出 n／m 人」與 2 分鐘的提醒倒數（`reminderSeconds.night`，只是提醒，不會自動揭曉）：
   - **豪賭**：再選「最多賭到第幾層」（1–3）。畫面列出每一層爆的機率與過關時累積變成多少：第 1 層擲到 1 就爆（1/6），過關 5 英鎊；第 2 層擲到 1–2 爆（2/6），過關 20 英鎊＋1 影響力；第 3 層擲到 1–3 爆（3/6），過關得秘寶 30 英鎊＋1 影響力。爆了累積歸零，另付 2 英鎊醫藥費（不夠就付到 0）。
   - **分贓**：選分贓的人平分 6 英鎊（捨去；只有 1 人就拿全部），每人記 1 點罪孽（人多到分 0 英鎊也照記）。
   - **睡覺**：什麼都不發生。
   選好按動作列的「送出：豪賭到第 2 層」（豪賭可以直接點第幾層）：選擇收成一行，揭曉前按「修改」可以改成別的再送一次，以最後一次為準。沒送出算睡覺。數值都在 `data/settings.json` 的選填設定（沒寫時用上面的預設值，見 [`docs/DATA-FORMAT.md`](../docs/DATA-FORMAT.md)）。
3. 全員送出後，所有畫面寫「大家都送出了，n 秒後揭曉」，倒數中還可以改；同黃昏，倒數到實際揭曉的時間（`nightRevealSeconds`，目前 3 秒，再加主持端的 1 秒緩衝），到 0 還沒揭曉寫「揭曉中…」，玩家畫面另有大數字倒數圈。主持端也可以按「提前揭曉」：馬上截止，沒送出的人算睡覺，約 1 秒後揭曉。
4. 揭曉時骰子由主持端擲（每一層一顆六面骰）。所有畫面不用重新整理就看到每個人的選擇與結果：豪賭寫每一層擲幾點、過關或爆了、拿到多少或付了醫藥費；分贓寫拿到多少與罪孽；自己選睡覺的寫「☾ 選了睡覺」，沒送出的寫「— 沒送出（算睡覺）」（主持端玩家表的「黑夜結果」也分這兩種，不只靠顏色）。玩家另外看到「你這一夜：英鎊 +20・影響力 +1」與現在的數字；沒送出的人看到「你沒有送出，算睡覺」。黑夜揭曉後，留在畫面上的黃昏結果不再寫「你現在」（那時的數字已經含黑夜的變化）。黑夜不動迷霧。
5. 揭曉前，主持端那一桌的「下一階段」停用並寫原因；揭曉後才能進下一回合日出。
6. 手牌上限（`handLimit`，目前 7 張）：黑夜期間（揭曉前後都可以），手牌超過上限的人畫面寫「手牌超過上限，選 2 張棄掉」與「已選 n／2」，點牌挑選（挑到的牌標「棄」），張數不對時按鈕寫「再選 1 張才能確定棄牌」；挑好按「選好了」，畫面寫「已選好：…（天亮前可以改）」。主持端那一桌寫「手牌超過上限、還沒挑：○○（要棄 2）」，玩家表標「要棄 n 張」或「已挑棄牌」，「下一階段」下面提醒「推進時沒挑的人會被隨機棄」（可以按，不用等）。黑夜的選擇已經送出、只剩棄牌時，「選好了」是主要按鈕。主持端推進到下一回合日出時，在同一筆發牌的最前面先棄牌：挑的合法（張數剛好、都是自己手上的牌）就照挑的棄，沒挑或不合法就隨機棄到上限；接著才領薪、抽牌、翻一般事件。被隨機棄的人，下一回合在玩家畫面最上面看到「手牌超過上限沒挑完，天亮時隨機棄了：〈牌名〉、〈牌名〉」（只有自己看得到，那一回合裡都顯示）。
7. 用固定的牌試：主持端網址加 `?seed=1`、三人一桌開局、白晝大家直接「結束這一輪」、黃昏按「提前揭曉」：前三回合翻到的一般事件與法案都不會改手牌張數，迷霧也不會越過 30（用純函式照主持端同一條亂數算的），所以第 2 回合黑夜每人剛好 8 張、要棄 1 張。第 1 回合黑夜：一人豪賭到第 2 層、一人分贓、一人睡覺，全員送出看倒數揭曉；第 2 回合黑夜：一人挑 1 張棄、另外兩人不挑，一人不送出，主持端按「提前揭曉」；第 3 回合日出看手牌：挑的那張不見了、沒挑的人被隨機棄到 7 張，再各抽 2 張。

### 事件

1. 開局（以及之後每回合日出發牌）時，每桌從自己那一疊一般事件翻一張（`data/settings.json` 沒寫 `sunriseEvents` 時是 1 張），對那一桌結算。主持端桌卡的「今日事件」一行（太長時「…」，點一下看全文）與玩家畫面最上面都出現「今日事件」：名稱、年代、牌面文字、效果與數字；玩家另外看到自己現在的英鎊、影響力與迷霧值。從日出到白晝結束一直顯示，出牌時也看得到；黃昏起收起來。
2. 任何結算（出牌、響應、黃昏揭曉、一般事件）讓迷霧值越過 30／60／90（要「大於」，剛好 30 不算）時，同一筆寫入就結算那個門檻的迷霧事件：所有畫面不用重新整理就出現「迷霧越過 30：《名稱》」與牌面文字（這一回合內一直顯示），數字跟著變。每個門檻每場只觸發一次；迷霧值旁邊寫「已觸發：30、60」。
3. 主持端每桌的「紀錄」（右側抽屜）與玩家畫面的「紀錄」分頁都有事件紀錄：本場翻過的一般事件與觸發過的迷霧事件，照發生順序。
4. 效果要指定一人的事件，這一版略過那一項（畫面寫一行提示）；效果還沒做好（todo）的事件照樣顯示，不結算。
5. 「偷」：行動牌寫 `偷英鎊3@指定`（一般牌）或 `偷英鎊2@出牌者`（響應卡），對方實際少多少、自己就拿多少。「最近出牌」寫成「從 ○○ 偷走 3 英鎊」（寫的是牌上的數量，4 級連鎖加倍；對方不夠時實際拿到的比較少，以座位上的數字為準）。目前的卡牌資料還沒有用到偷的牌（企劃會改）。
6. 正式資料第 1 回合不容易讓迷霧越過 30；畫面測試是用測試複本跑的（只在瀏覽器裡把一張牌的迷霧改成 +31、兩張牌改成偷），資料檔沒有改。

### 結束一場、看分數

1. 主持端每桌開局後，桌卡底部有日落鐘：「開局 n 分・剩 n 分」（從那一桌按「開始」的伺服器時間算，`data/settings.json` 的 `sunsetMinutes`，目前 75 分鐘）。時間到了寫「時間到了」，色帶出現「最後一回合」。
2. 日落鐘到了、到了第 12 回合（`maxRounds`，安全上限），或主持端按了那一桌的「這回合結束後算分」（試玩時間不夠時用；按了變成「取消提早算分」，可以取消），這一回合就是最後一回合：玩家畫面寫「這是最後一回合」，主持端那一桌黑夜揭曉後，「下一階段」變成「下一階段（算分）」。按下去不進下一回合，那一桌直接終局（不發牌、不棄牌、不翻事件），各桌各自結束。黑夜還沒揭曉時一樣不能按。最後一夜手牌超過上限的人不用棄牌，畫面寫「算分時超過上限的照上限 7 張算」（天命判定裡的手牌先套手牌上限 `handLimit` 再比）。
3. 終局後所有畫面不用重新整理就看到結算。主持端那一桌的桌卡是名次摘要（名次、總分、天命達成與否），「下一階段」不再出現；按「展開結算明細」開右側抽屜：照名次排，每人的天命（內容、達成條件、達成或沒達成）、資產換算（英鎊每 5 點 1 分、影響力每 3 點 1 分，各自捨去）、公共成就（議會之聲、齒輪大師各 3 分）、罪孽扣分（每 2 點扣 1 分）與總分的算式。玩家畫面最上面是自己的名次、總分與分數明細（天命、資產、公共成就、罪孽、總分），底下是全桌名次（每個人的階層與天命達成與否），按「看全桌天命」列出每個人的天命內容（終局時公開）。
4. 天命表「判定」欄空白的天命，終局時寫「待主持人判定」（先算 0 分）；桌卡寫「待判定 n 份天命」；主持端在結算明細抽屜裡按「判定：達成 +10」或「判定：沒達成」，總分與名次在所有畫面跟著改，按錯了可以按「改成…」再改。目前的 `data/destinies.json` 12 張都有企劃給的「判定」，終局時自動判定；之後新增或「判定」留空的天命才要主持端判定。
5. 名次：總分高的在前，同分比英鎊，再同就並列。分數的數值都是設定（`data/settings.json` 沒寫時用預設值，見 [`docs/DATA-FORMAT.md`](../docs/DATA-FORMAT.md)）。
6. 快速試：開局後第 1 回合就按「這回合結束後算分」，白晝大家直接「結束這一輪」、黃昏與黑夜按「提前揭曉」，黑夜揭曉後按「下一階段（算分）」。畫面測試是用測試複本跑的（只在瀏覽器裡把日落鐘改成 2 分鐘、天命加上企劃的 12 張判定），資料檔沒有改。

### 兩場制：開第 2 場

第 2 場在同一間房、同一桌接著打；座位照舊，每個座位第 1 場的階層傳給另一個座位（傳法在 `js/game.js` 的 `rotateSeats`），英鎊、影響力、手牌、天命、日落鐘都重來，最後看兩場合計。

1. 某一桌第 1 場終局、天命都判定了以後，主持端桌卡出現「開第 2 場」（還有待判定的天命時停用，寫出張數）。按下去會先確認：開了第 2 場，第 1 場的結算就鎖住，不能再改。頂列的「已結束的桌全部開第 2 場」一次開所有第 1 場結束的桌，有待判定的桌跳過並列出來。
2. 開了之後，玩家手機不用重新整理就換成「第 2 場・準備中」：寫自己第 2 場的階層、是誰交過來的、自己的角色卡要交給誰；第 1 場的結算收在「紀錄」分頁。現場這時交接角色卡。
3. 主持端那一桌變成「第 2 場・未開局」，桌卡是座位預覽（第 1 場 → 第 2 場的階層、由誰交過來、參加與否）。有人不打了就按「勾選參加」把他勾掉（他的座位這場空著，傳給那個座位的階層第 2 場沒有人坐）；第 1 場之後才加入的人不能勾（第 2 場不收新人）。勾選只存在這台主持裝置，換一台要重勾。核對好按「開始第 2 場」。
4. 第 2 場開局後，玩家看到新的手牌與天命，行動分頁最上面有一張換場說明（到第 1 回合白晝開始為止），教學提示不再出現；被勾掉的人看到「這一場你沒有座位」與自己第 1 場的結算。之後的流程跟第 1 場一樣，色帶與玩家畫面的標籤寫「第 2 場」。
5. 第 2 場終局後，玩家畫面最上面是兩場合計的名次與算式（第 1 場＋第 2 場，同分並列，不比英鎊），接著是第 2 場的分數明細、全桌兩場合計，以及「第 1 場結算」（只讀）。主持端結算明細的三段見上面「結算明細」；第 2 場的天命判定後，合計在所有畫面跟著改。

### 固定手牌（只有模擬器）

主持端網址加 `?seed=<整數>`（例如 `http://127.0.0.1:5050/?seed=3`），開局洗牌、隨機棄牌就用固定種子，每次開出來的牌一樣，方便照著同一副牌測試畫面；座位 1 的手牌只看種子，誰坐座位 1 仍是隨機的。正式專案不認這個參數。

### 試備援主持

再開一個分頁當備援裝置：`http://127.0.0.1:5050/?slot=b`。

1. 在備援分頁的首頁按「開房／接手房間」，在「接手已經開的房間」輸入房號，按「送出備援主持申請」。畫面會顯示 4 碼確認碼與「等待主持端核准」。
2. 回主持端分頁，頂列的「備援主持申請 1」變醒目；點開會列出這筆申請與同一組確認碼，核對相同後按「核准」（或「拒絕」）。
3. 備援分頁自動切到主持畫面，之後兩個分頁都能按「下一階段」；同時按也只會前進一步。
4. 主持端分頁按頂列的「離開」回首頁，再用同一個房號在「接手已經開的房間」送出，會直接回到主持畫面。

關掉玩家分頁，主持畫面會把那位玩家標成「離線」；兩個主持分頁都關掉時，玩家畫面會顯示「主持端目前離線」。

## 正式環境

`js/config.js` 有本機模擬器與正式專案兩組設定，依開啟頁面的網址選一組：

| 網址 | 連到 |
|---|---|
| 帶 `?env=emu` | 本機模擬器 |
| 帶 `?env=prod` | 正式專案 |
| 都沒帶，主機是 `localhost`、`127.0.0.1` 或 `::1` | 本機模擬器 |
| 都沒帶，其他主機 | 正式專案 |

推上 GitHub Pages 後的網址是 <https://kiresakura.github.io/one-day-briton/play/>，不用加參數就連正式專案。

本機加 `?env=prod`（例如 `http://localhost:5050/?env=prod`，可以再加 `&slot=p1`）也會連正式專案，開的房、加入的玩家都**寫進正式資料庫**，而且房間不會自動刪除，只在驗收時用。請用 `localhost` 開：正式專案的已授權網域有 `localhost`，沒有 `127.0.0.1`。

設定裡的 `apiKey` 等值是公開的識別碼，不是密碼；誰能讀寫由根目錄的 `database.rules.json` 決定，發布方式見 [`docs/ARCHITECTURE.md`](../docs/ARCHITECTURE.md) 的「環境」。

```sh
npm run test:sync   # 啟動模擬器，用 js/store.js 測同步與安全規則（含私密資料與牌庫的讀寫權限、開局與發牌不重複、出牌請求的權限、結算與 version 守門、響應窗口與時間到、票的讀寫權限、倒數揭曉與提前揭曉、日出一般事件、迷霧事件與事件紀錄的規則、偷、黑夜的選擇與挑棄牌的規則、黑夜的倒數揭曉與提前揭曉、日出照挑的棄牌、日落鐘與提早收場、終局那一筆與 `final` 的規則、主持端勾天命）
npm run test:all    # 兩者都跑
npm run data:check  # 只檢查 play/data/ 的卡牌資料檔
npm run data:import -- <CSV 資料夾>   # 試算表匯出的 CSV 轉成 play/data/，寫完自動檢查
```

`test:sync` 會印出許多 `permission_denied` 警告，那是「被拒絕才算通過」的測試留下的，以最後的統計為準。

## 連接埠

全部只綁 `127.0.0.1`，設定在根目錄的 `firebase.json`。

| 用途 | 連接埠 |
|---|---|
| 網頁（hosting） | 5050 |
| 匿名登入（auth） | 9099 |
| 資料庫（database） | 9000 |
| 模擬器控制（hub） | 4400 |
| 模擬器記錄（logging） | 4500 |

網頁不用預設的 5000，因為 macOS 的 AirPlay 接收器會佔用它。改了 9099 或 9000 的話，`js/config.js` 要跟著改。

## 自行託管的 SDK

`vendor/firebase/` 裡的三個檔案來自 npm 的 `firebase` 套件（版本與雜湊見 `vendor/firebase/VERSION.txt`，授權為 Apache-2.0）。官方檔案彼此之間是用 `https://www.gstatic.com/…` 的網址互相匯入，複製時已改寫成相對路徑，所以頁面只會向自己的主機要檔案。`firebase-app.js` 裡還留有兩處該網址的字串，那是 SDK 用來標示自己名稱的常數，不會發出請求。

`js/store.js` 寫的是 `firebase/app` 這種模組名稱：瀏覽器靠 `index.html` 裡的 import map 對到 `vendor/firebase/`，Node 測試則用 `node_modules` 裡的同一版套件。

升級 SDK 時改 `package.json` 的版本、`npm install`，再重新產生：

```sh
npm run vendor
```
